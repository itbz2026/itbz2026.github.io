Windows Server

Grundlagen und Administration

Grundlagen

Überblick und typische Rollen

Windows Server stellt zentrale IT-Dienste für Benutzer, Geräte und Anwendungen bereit.

  • AD DS: Identitäten und Computer zentral verwalten.
  • DNS: Namen in IP-Adressen auflösen.
  • DHCP: IP-Konfiguration automatisch vergeben.
  • File Services: Dateien und Freigaben bereitstellen.
  • Hyper-V: Virtuelle Maschinen betreiben.
Nur benötigte Rollen installieren, Updates einspielen und Änderungen dokumentieren.
Checkliste

Erste Konfiguration nach Installation

  1. Servernamen festlegen und neu starten.
  2. Statische IP und korrekten DNS-Server konfigurieren.
  3. Zeitzone und Zeitsynchronisierung prüfen.
  4. Updates installieren.
  5. Firewall und Remoteverwaltung gezielt konfigurieren.
  6. Benötigte Rollen installieren und testen.
  7. Backup und Monitoring einrichten.

Active Directory

Identitäts- und Gruppenverwaltung

Konzepte

Wichtige AD-Begriffe

  • Domain: administrative Sicherheits- und Replikationsgrenze.
  • Domain Controller: Server mit AD DS, der Anmeldungen verarbeitet.
  • OU: Container zur Strukturierung und Delegation.
  • Group Policy (GPO): zentrale Konfiguration von Benutzern und Computern.
  • Group: bündelt Berechtigungen für Benutzer und Geräte.
Berechtigungen möglichst über Gruppen vergeben, nicht direkt an einzelne Benutzer.
PowerShell

AD-Benutzer und Gruppen prüfen

Get-ADUser -Identity max.mustermann
Get-ADUser -Filter * -SearchBase "OU=Users,DC=example,DC=local"
Get-ADGroupMember -Identity "IT-Admins"
Get-ADDomain
Get-ADDomainController -Filter *

Die ActiveDirectory-PowerShell-Module und passende Rechte werden benötigt.

Networking

Grundlagen

IP, Gateway und Subnetz

  • IP-Adresse: logische Adresse eines Netzwerkgeräts.
  • Subnetzmaske/CIDR: bestimmt den Netz- und Hostanteil.

VLAN

VLAN erstellen und Access-Port zuweisen

Ein VLAN trennt ein Layer-2-Netz logisch in eigene Broadcast-Domänen.

show vlan brief
configure terminal
vlan 10
 name MANAGEMENT
exit
interface gigabitEthernet 0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
end
show vlan brief

Weitere Befehle: show vlan id 10, no vlan 10, show interfaces switchport.

Trunking

Mehrere VLANs über eine Verbindung transportieren

configure terminal
interface gigabitEthernet 0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30,99
 switchport trunk native vlan 99
 no shutdown
end
show interfaces trunk
show interfaces gi0/24 switchport
Native VLAN und erlaubte VLANs müssen an beiden Enden zusammenpassen. Prüfe die Plattformunterstützung; manche Modelle benötigen zusätzliche oder abweichende Befehle.

Inter-VLAN Routing

SVIs auf einem Layer-3-Switch

configure terminal
ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
interface vlan 20
 ip address 192.168.20.1 255.255.255.0
 no shutdown
exit
end
show ip interface brief
show ip route
Beispiel: VLAN 10 = 192.168.10.0/24, Gateway 192.168.10.1; VLAN 20 = 192.168.20.0/24, Gateway 192.168.20.1. Die SVIs benötigen ein aktives VLAN und je nach Modell einen aktiven Layer-2-Port im VLAN.
STP

Spanning Tree Protocol

STP verhindert Layer-2-Schleifen. Rapid-PVST ist eine Cisco-Implementierung mit separaten STP-Instanzen pro VLAN.

show spanning-tree
show spanning-tree summary
show spanning-tree vlan 10
show spanning-tree root
show spanning-tree detail

configure terminal
spanning-tree mode rapid-pvst
spanning-tree vlan 10 root primary
interface gigabitEthernet 0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
end
show spanning-tree
PortFast und BPDU Guard nur auf geeigneten Endgeräte-Ports verwenden, nicht auf Switch-Uplinks. Vor Änderungen Root-Bridge und Topologie prüfen.
EtherChannel · LACP

Mehrere Links bündeln

show etherchannel summary
show etherchannel detail

configure terminal
interface range gigabitEthernet 0/1-2
 channel-group 1 mode active
 no shutdown
exit
interface port-channel 1
 switchport mode trunk
exit
end
show etherchannel summary

active und passive verwenden LACP. Beide Seiten benötigen kompatible Einstellungen: gleiche VLAN-/Trunk-Konfiguration, Geschwindigkeit und Duplex. Statisches mode on nur verwenden, wenn beide Enden passend konfiguriert sind.

ACL

Standard-ACL – Beispiel

configure terminal
access-list 10 permit 192.168.10.0 0.0.0.255
access-list 10 deny any
interface vlan 20
 ip access-group 10 in
exit
end
show access-lists
show ip access-lists
ACLs haben am Ende eine implizite deny-Regel. Prüfe Reihenfolge, Richtung und Auswirkungen vor dem Anwenden. Beispielkonfigurationen zuerst in einer Testumgebung prüfen.
Port Security

MAC-Adressen auf einem Access-Port begrenzen

configure terminal
interface gigabitEthernet 0/1
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
end
show port-security
show port-security interface gi0/1

Bei restrict werden nicht erlaubte Frames verworfen und Verstöße gezählt. Die konkrete Verfügbarkeit hängt vom Switch-Modell und IOS ab.

Hinweise

Sicher arbeiten

  • Vor Änderungen immer show running-config prüfen und eine Sicherung erstellen.
  • Nach erfolgreichen Änderungen copy running-config startup-config ausführen.
  • VLAN- und Trunk-Konfigurationen auf beiden Seiten kontrollieren.
  • STP nicht leichtfertig deaktivieren; es schützt vor Layer-2-Schleifen.
  • ACLs können Verbindungen blockieren; vorab testen und Rückfallplan bereithalten.
  • Cisco-Befehle unterscheiden sich je nach IOS-Version und Gerätemodell.
  • Mit Cisco Packet Tracer oder in einer isolierten Testumgebung üben.

Rechte

Dateiberechtigungen

Linux-Rechte gelten für Eigentümer, Gruppe und andere. Die Rechte sind Lesen (r), Schreiben (w) und Ausführen (x).

ls -l datei.txt

Virtualisierung

Virtuelle Maschinen und Hypervisor

Grundlagen

Wichtige Begriffe

Virtualisierung teilt physische Hardware in isolierte virtuelle Systeme auf. Eine VM nutzt virtuelle CPU, RAM, Datenträger und Netzwerkadapter.

  • Hypervisor Typ 1: läuft direkt auf der Hardware, z. B. Hyper-V oder ESXi.
  • Hypervisor Typ 2: läuft als Anwendung auf einem Host, z. B. VMware Workstation.
  • Snapshot: speichert einen kurzfristigen Zustand einer VM.
  • Virtual Switch: verbindet virtuelle Netzwerkadapter.
  • Template: Vorlage für neue virtuelle Maschinen.
Snapshots sind kein Backup. Für dauerhafte Datensicherung unabhängige Backups verwenden.

IT Security

Schutz von Systemen und Daten

Best Practices

Server-Sicherheitsbaseline

  • Sicherheitsupdates zeitnah installieren.
  • Einzigartige Passwörter und MFA einsetzen.
  • Least Privilege: nur notwendige Rechte vergeben.
  • Firewall: nur erforderliche Ports und Quellnetze freigeben.
  • Unnötige Dienste deaktivieren.
  • Logs sammeln und regelmäßig prüfen.
  • Backups verschlüsseln und Restore testen.
  • Administrationszugänge besonders schützen.

Backup & Recovery

Datensicherung und Wiederherstellung

Strategie

3-2-1-Regel

  • 3 Datenkopien: Original plus zwei Backups.
  • 2 unterschiedliche Speichermedien oder Systeme.
  • 1 Kopie extern oder offline aufbewahren.

Backup-Checkliste

  1. Kritische Daten und Systeme bestimmen.
  2. Backup-Intervall und Aufbewahrung definieren.
  3. Zugriff auf Backups begrenzen.
  4. Backups überwachen und Fehler melden.
  5. Wiederherstellung regelmäßig testen.
Ein Backup ist erst verlässlich, wenn die Wiederherstellung erfolgreich getestet wurde.

Troubleshooting

Fehler systematisch eingrenzen

Methode

Standard-Vorgehensweise

  1. Problem beschreiben: Was funktioniert nicht und seit wann?
  2. Umfang bestimmen: Ein Benutzer, ein Gerät oder mehrere Systeme?
  3. Änderungen prüfen: Updates, Konfiguration, Netzwerk oder Rechte.
  4. Logs prüfen: Fehlermeldungen und Zeitstempel sichern.
  5. Hypothese testen: Eine Änderung nach der anderen.
  6. Lösung verifizieren: Funktion und Nebenwirkungen prüfen.
  7. Dokumentieren: Ursache, Lösung und Prävention festhalten.
