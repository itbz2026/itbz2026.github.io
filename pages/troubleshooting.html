Troubleshooting

Fehler eingrenzen, Ursache finden und Lösung dokumentieren

Erweiterte Befehls- und Themenreferenz: Alle zusätzlichen Befehle, Parameter, Praxisbeispiele und Diagnose öffnen →
Methode

Standard-Vorgehensweise

  1. Problem beschreiben: Was funktioniert nicht, seit wann und mit welcher Fehlermeldung?
  2. Umfang bestimmen: Ein Benutzer, ein Gerät, ein Standort oder mehrere Systeme?
  3. Änderungen prüfen: Updates, Konfigurationen, Berechtigungen und Netzwerkänderungen.
  4. Beweise sammeln: Logs, Zeitstempel, Status und reproduzierbare Schritte sichern.
  5. Hypothese bilden: mögliche Ursachen priorisieren.
  6. Kontrolliert testen: jeweils nur eine Änderung durchführen.
  7. Verifizieren: Funktion und Nebenwirkungen prüfen.
  8. Dokumentieren: Ursache, Lösung und Prävention festhalten.
Netzwerk

Keine Netzwerkverbindung

  1. Physische Verbindung, WLAN und Interface-Status prüfen.
  2. IP-Adresse, Subnetz und Gateway prüfen.
  3. Gateway und danach externe IP testen.
  4. DNS-Auflösung testen.
  5. Routing, VLAN, ACL und Firewall prüfen.
  6. Zielport und Anwendung testen.
ipconfig /all
ping 192.168.1.1
route print
nslookup example.com
tracert example.com
Test-NetConnection example.com -Port 443
ip addr
ip route
ping -c 4 192.168.1.1
dig example.com
ss -tulpn
DNS

Namensauflösung funktioniert nicht

  • Welcher DNS-Server ist konfiguriert?
  • Ist die IP des DNS-Servers erreichbar?
  • Funktioniert die Abfrage direkt gegen den zuständigen DNS-Server?
  • Stimmen A/AAAA-, CNAME-, PTR- oder SRV-Einträge?
  • Ist ein Cacheproblem möglich?
ipconfig /all
ipconfig /flushdns
nslookup hostname.example.local
Resolve-DnsName hostname.example.local
dig hostname.example.local
Windows

Windows-Dienst startet nicht

Get-Service
Get-Service -Name SERVICE
Get-WinEvent -LogName System -MaxEvents 50
sc.exe query SERVICE
sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth

Abhängigkeiten, Dienstkonto, Berechtigungen, Starttyp, freie Ressourcen und passende Ereignisprotokolle kontrollieren.

Linux

Linux-Dienst oder Server fehlerhaft

systemctl status SERVICE
systemctl --failed
journalctl -u SERVICE -b
journalctl -p err -b
df -h
free -h
dmesg -T | tail -n 50
ss -tulpn

Prüfe zusätzlich Dateirechte, Konfigurationssyntax, Speicherplatz, Inodes und Abhängigkeiten.

Docker

Container startet nicht oder ist nicht erreichbar

docker ps -a
docker compose ps
docker logs --tail 100 CONTAINER
docker inspect CONTAINER
docker stats
docker network ls
docker volume ls
ss -tulpn

Image, Exit-Code, Healthcheck, Mounts, UID/GID, Umgebungsvariablen, Netzwerk und Port-Mapping prüfen. Vor Prune- oder Volume-Löschaktionen Backupstatus kontrollieren.

Virtualisierung

VM ist langsam oder nicht erreichbar

  • Host-Auslastung, CPU-Overcommit und RAM-Druck prüfen.
  • Datastore-Latenz, freie Kapazität und Snapshot-Ketten prüfen.
  • Virtuelle Netzwerkkarte, Portgroup, VLAN und vSwitch prüfen.
  • Guest-Tools und Gastbetriebssystem-Logs prüfen.
  • Host- und VM-Zeit synchronisieren.
