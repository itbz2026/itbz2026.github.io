Interfaces & Ports

Ports anzeigen und konfigurieren

show interfaces

configure terminal
interface gigabitEthernet 0/1

 no shutdown
end

show ip interface brief ist ein schneller Überblick über IP-Adressen und Interface-Zustände.

VLAN

VLAN erstellen und Access-Port zuweisen

Ein VLAN trennt ein Layer-2-Netz logisch in eigene Broadcast-Domänen.

show vlan brief
configure terminal
vlan 10
 name MANAGEMENT
exit
interface gigabitEthernet 0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
end
show vlan brief

Weitere Befehle: show vlan id 10, no vlan 10, show interfaces switchport.

Trunking

Mehrere VLANs über eine Verbindung transportieren

configure terminal
interface gigabitEthernet 0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30,99
 switchport trunk native vlan 99
 no shutdown
end
show interfaces trunk
show interfaces gi0/24 switchport
Native VLAN und erlaubte VLANs müssen an beiden Enden zusammenpassen. Prüfe die Plattformunterstützung; manche Modelle benötigen zusätzliche oder abweichende Befehle.

Routing

Routing-Tabelle und statische Route

show ip route
show ip protocols
show ip interface brief
show arp
ping 192.168.1.1
traceroute 8.8.8.8

configure terminal
ip routing
ip route 192.168.2.0 255.255.255.0 192.168.1.1
end

Eine statische Route wird mit no ip route 192.168.2.0 255.255.255.0 192.168.1.1 entfernt.

Inter-VLAN Routing

SVIs auf einem Layer-3-Switch

configure terminal
ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
interface vlan 20
 ip address 192.168.20.1 255.255.255.0
 no shutdown
exit
end
show ip interface brief
show ip route
Beispiel: VLAN 10 = 192.168.10.0/24, Gateway 192.168.10.1; VLAN 20 = 192.168.20.0/24, Gateway 192.168.20.1. Die SVIs benötigen ein aktives VLAN und je nach Modell einen aktiven Layer-2-Port im VLAN.
STP

Spanning Tree Protocol

STP verhindert Layer-2-Schleifen. Rapid-PVST ist eine Cisco-Implementierung mit separaten STP-Instanzen pro VLAN.

show spanning-tree
show spanning-tree summary
show spanning-tree vlan 10
show spanning-tree root
show spanning-tree detail

configure terminal
spanning-tree mode rapid-pvst
spanning-tree vlan 10 root primary
interface gigabitEthernet 0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
end
show spanning-tree
PortFast und BPDU Guard nur auf geeigneten Endgeräte-Ports verwenden, nicht auf Switch-Uplinks. Vor Änderungen Root-Bridge und Topologie prüfen.
EtherChannel · LACP

Mehrere Links bündeln

show etherchannel summary
show etherchannel detail

configure terminal
interface range gigabitEthernet 0/1-2
 channel-group 1 mode active
 no shutdown
exit
interface port-channel 1
 switchport mode trunk
exit
end
show etherchannel summary

active und passive verwenden LACP. Beide Seiten benötigen kompatible Einstellungen: gleiche VLAN-/Trunk-Konfiguration, Geschwindigkeit und Duplex. Statisches mode on nur verwenden, wenn beide Enden passend konfiguriert sind.

ACL

Standard-ACL – Beispiel

configure terminal
access-list 10 permit 192.168.10.0 0.0.0.255
access-list 10 deny any
interface vlan 20
 ip access-group 10 in
exit
end
show access-lists
show ip access-lists
ACLs haben am Ende eine implizite deny-Regel. Prüfe Reihenfolge, Richtung und Auswirkungen vor dem Anwenden. Beispielkonfigurationen zuerst in einer Testumgebung prüfen.
Port Security

MAC-Adressen auf einem Access-Port begrenzen

configure terminal
interface gigabitEthernet 0/1
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
end
show port-security
show port-security interface gi0/1

Bei restrict werden nicht erlaubte Frames verworfen und Verstöße gezählt. Die konkrete Verfügbarkeit hängt vom Switch-Modell und IOS ab.

Hinweise

Sicher arbeiten

  • Vor Änderungen immer show running-config prüfen und eine Sicherung erstellen.
  • Nach erfolgreichen Änderungen copy running-config startup-config ausführen.
  • VLAN- und Trunk-Konfigurationen auf beiden Seiten kontrollieren.
  • STP nicht leichtfertig deaktivieren; es schützt vor Layer-2-Schleifen.
  • ACLs können Verbindungen blockieren; vorab testen und Rückfallplan bereithalten.
  • Cisco-Befehle unterscheiden sich je nach IOS-Version und Gerätemodell.
  • Mit Cisco Packet Tracer oder in einer isolierten Testumgebung üben.

VTP · VLAN Trunking Protocol

VTP verstehen: Version 1, 2 und 3

VTP verteilt VLAN-Informationen innerhalb derselben VTP-Domain über Trunk-Verbindungen. Alle Switches müssen denselben Domain-Namen verwenden. VTP ersetzt keine Trunk-Konfiguration.

VersionWichtige EigenschaftenHinweis
VTP v1Grundlegende VLAN-Verteilung; klassische VTP-FunktionLegacy; nur einsetzen, wenn erforderlich
VTP v2Verbesserte Behandlung unbekannter TLVs; zusätzliche KonsistenzfunktionenNicht interoperabel mit v1 im selben Domain-Betrieb, wenn v2 aktiviert ist
VTP v3Unterstützt Extended VLANs und Private VLANs; Primary-Server-Konzept; verbesserte KontrolleFür moderne unterstützte Umgebungen bevorzugt; Kompatibilität prüfen

Wichtige VTP-Modi

  • Server: Kann VLAN-Datenbank ändern und verteilen. Bei VTP v3 muss ein Primary Server Änderungen an der VLAN-Datenbank vornehmen.
  • Client: Übernimmt VLAN-Informationen und kann sie nicht lokal verwalten.
  • Transparent: Verwaltet VLANs lokal; leitet VTP-Nachrichten je nach Version/Plattform weiter, nimmt aber nicht an der VLAN-Verteilung teil.
  • Off: VTP-Nachrichten werden nicht weitergeleitet; Verfügbarkeit abhängig von Plattform und Version.

VTP-Status prüfen

show vtp status
show vtp counters
show vlan brief
show interfaces trunk
show running-config | include vtp

Beispiel: VTP v2 – Server und Client

Nur in einer isolierten Testumgebung verwenden. Beispiel-Domain: LABNET.

! Auf dem Server-Switch
configure terminal
vtp domain LABNET
vtp version 2
vtp mode server
vtp password MeinVtpPasswort
end
show vtp status

! Auf dem Client-Switch
configure terminal
vtp domain LABNET
vtp version 2
vtp mode client
vtp password MeinVtpPasswort
end
show vtp status

! Auf beiden Switches: Uplink als Trunk konfigurieren
configure terminal
interface gigabitEthernet 0/24
 switchport mode trunk
 no shutdown
end

Beispiel: VTP v3 – Primary Server

! Auf jedem Switch der Domain
configure terminal
vtp domain LABNET
vtp version 3
vtp password MeinVtpPasswort
end

! Auf dem vorgesehenen Primary Server
vtp primary vlan
show vtp status

! VLAN zentral erstellen
configure terminal
vlan 10
 name CLIENTS
vlan 20
 name SERVERS
end
show vlan brief
show vtp status

VTP sicher prüfen – bevor du einen Switch verbindest

  • show vtp status: Version, Domain, Modus und Configuration Revision kontrollieren.
  • Ein Switch mit höherer Configuration Revision kann in bestimmten VTP-Szenarien unerwartet VLAN-Informationen verteilen.
  • Vor dem Anschluss eines gebrauchten Switches VTP-Modus, Domain und Revision prüfen; bei Unsicherheit zuerst isolieren und sauber vorbereiten.
  • VTP-Passwort und identische Domain auf allen teilnehmenden Geräten konfigurieren.
  • VTP v3 Primary-Server-Rolle bewusst vergeben.
  • Viele Netzwerke nutzen bewusst vtp mode transparent oder vtp mode off, um unerwünschte zentrale VLAN-Verteilung zu vermeiden.
Achtung: VTP kann bei falscher Domain-/Revision-Konstellation VLAN-Konfigurationen verändern. Niemals ungeprüft einen gebrauchten Switch in ein produktives VTP-Netz stecken. Befehle und unterstützte Modi hängen vom Switch-Modell und IOS/IOS XE ab.

Beispiel: WLAN-Konfiguration mit WPA2-PSK

Beispielwerte ersetzen: WLAN-ID 10, SSID CORP-WIFI, Policy Profile CORP-POLICY, VLAN 20. Vor produktiver Nutzung Sicherheitsvorgaben prüfen; WPA2-PSK ist hier nur ein einfaches Laborbeispiel.

configure terminal
wlan CORP-WIFI 10 CORP-WIFI
 security wpa psk set-key ascii 0 CHANGE-ME-TO-A-STRONG-KEY
 no shutdown
exit

wireless profile policy CORP-POLICY
 vlan 20
 no shutdown
exit

wireless tag policy CORP-TAG
 wlan CORP-WIFI policy CORP-POLICY
exit

! Tag einem AP zuweisen – AP-Namen anpassen
ap name AP-NAME
 policy-tag CORP-TAG
end

show wlan summary
show wireless tag policy detailed

Die WLAN-Beispielkonfiguration ist ein vereinfachtes Template. Je nach IOS-XE-Release, Sicherheitsmodus, AAA/RADIUS, VLAN-Design und AP-Modell können zusätzliche Einstellungen erforderlich sein. Vor Anwendung Syntax mit ? und der passenden Cisco-Konfigurationsanleitung prüfen.
