Linux – Erweiterte Referenz

Systematisch sortierte Befehle, Optionen, Praxisbeispiele und Diagnose. Platzhalter wie HOST, USER, SERVICE und IP an die eigene Umgebung anpassen.

Wichtiger Hinweis: Befehle und Optionen hängen von Betriebssystem, Version, installierten Modulen und Berechtigungen ab. Vor produktiven Änderungen Herstellerdokumentation, Testumgebung, Backup und Rollback prüfen. Beispiele sind Vorlagen, keine universellen Produktionskonfigurationen.
01 · Referenz

Dateisystem und Storage

Dateisystemtyp, Mounts, Speicherplatz und Inodes getrennt prüfen. Volle Inodes können Schreibfehler trotz freiem Speicher verursachen.

lsblk -f
df -hT
df -ih
findmnt
blkid
sudo du -xhd1 /var

Parameter und Hinweise: df zeigt Dateisystembelegung; du zeigt Verzeichnisverbrauch; lsblk zeigt Blockgeräte und Partitionen.

02 · Referenz

systemd und Dienste

systemctl steuert systemd-Units. enable konfiguriert Autostart, start startet sofort; beides sind unterschiedliche Aktionen.

systemctl status ssh
systemctl start ssh
systemctl enable ssh
systemctl enable --now ssh
systemctl list-units --failed
systemctl cat ssh

Parameter und Hinweise: --now kombiniert enable/disable mit sofortiger Aktion. Vor Änderungen Unit-Datei und Abhängigkeiten prüfen.

03 · Referenz

Journal und Logs

journalctl filtert systemd-Journal nach Dienst, Boot, Priorität und Zeitraum.

journalctl -b
journalctl -u ssh --since today
journalctl -p warning..alert
journalctl -f
journalctl --disk-usage

Parameter und Hinweise: -b aktueller Boot; -u Dienst; -p Priorität; -f Follow. Logs können sensible Daten enthalten.

04 · Referenz

Netzwerk mit iproute2

ip ersetzt viele ältere Werkzeuge wie ifconfig und route. Änderungen mit ip link/ip addr/ip route sind häufig temporär.

ip -br link
ip -br addr
ip route
ip neigh
ip link show
resolvectl status

Parameter und Hinweise: ip addr add und ip route add ändern den Laufzeitstatus; persistente Konfiguration erfolgt distributionsabhängig, z. B. NetworkManager oder systemd-networkd.

05 · Referenz

Paketverwaltung APT

APT verwaltet Debian-Pakete und Abhängigkeiten. Erst Paketlisten aktualisieren, dann geplante Upgrades prüfen.

sudo apt update
apt list --upgradable
sudo apt upgrade
apt-cache policy openssh-server
apt show nginx
sudo apt install nginx
sudo apt remove nginx

Parameter und Hinweise: apt update aktualisiert Paketlisten, installiert aber keine Updates. apt full-upgrade kann Pakete entfernen, daher Änderungsvorschau lesen.

06 · Referenz

Benutzer und Rechte

Linux-Rechte bestehen aus Owner, Group und Other. sudo delegiert privilegierte Befehle; Gruppenmitgliedschaft erfordert meist neue Anmeldung.

id
getent passwd USER
getent group sudo
sudo usermod -aG sudo USER
stat /etc/ssh/sshd_config
chmod 640 FILE
chown root:root FILE

Parameter und Hinweise: -aG fügt Gruppen hinzu, ohne bestehende Zusatzgruppen zu ersetzen. chmod rekursiv nur mit bewusstem Zielpfad verwenden.

07 · Referenz

SSH sicher betreiben

SSH-Zugriff über Schlüssel, eingeschränkte Konten und aktuelle Kryptografie schützen. Konfiguration vor Reload validieren.

ssh-keygen -t ed25519
ssh-copy-id USER@HOST
sshd -t
sudo systemctl reload ssh
sudo journalctl -u ssh -n 50

Parameter und Hinweise: SSH-Server-Konfigurationspfad meist /etc/ssh/sshd_config. Vor Abschalten von Passwortauthentifizierung einen zweiten getesteten Schlüsselzugang bereithalten.

08 · Referenz

Firewall nftables und UFW

Firewallregeln nur mit bekanntem Regelwerk ändern. Remote-SSH zuerst erlauben und Lockout vermeiden.

sudo ufw status verbose
sudo ufw allow from 192.0.2.0/24 to any port 22 proto tcp
sudo ufw enable
sudo nft list ruleset

Parameter und Hinweise: UFW ist Frontend; nftables ist Linux-Netfilter-Regelwerk. Nicht mehrere konkurrierende Firewallmanager parallel konfigurieren.

09 · Referenz

Prozesse und Performance

CPU, RAM, Load Average, Prozesse und offene Dateien gemeinsam bewerten.

top
ps aux --sort=-%cpu | head
free -h
uptime
vmstat 1 5
iostat -xz 1 5
ss -tulpn

Parameter und Hinweise: Load Average ist keine direkte CPU-Prozentzahl. iostat gehört zum sysstat-Paket.

10 · Referenz

Cron und Timer

Wiederkehrende Jobs mit Cron oder systemd-Timern planen. Ausführungsumgebung und Fehlerprotokollierung berücksichtigen.

crontab -l
sudo crontab -e
systemctl list-timers --all
systemctl status apt-daily.timer

Parameter und Hinweise: Cron hat eine reduzierte Umgebung; absolute Pfade verwenden. Kritische Jobs mit Logging, Exit-Code-Prüfung und Monitoring versehen.

Troubleshooting

Systemzustand und Ressourcen prüfen

CPU, RAM, Load, Dateisysteme und fehlgeschlagene Units als erste Diagnose erfassen.

uptime
free -h
top
ps aux --sort=-%mem | head
df -hT
df -ih
systemctl --failed
journalctl -p err -b --no-pager
Hohe Load Average immer zusammen mit CPU-Auslastung, I/O-Wait und Prozesszuständen interpretieren.
Troubleshooting

Netzwerk und offene Ports prüfen

Adresse, Route, DNS und Listener getrennt testen, um Fehler einzugrenzen.

ip -br address
ip route
ip neigh
getent hosts example.com
ss -tulpn
ping -c 3 <GATEWAY-IP>
curl -I https://example.com
Ping kann durch Firewalls blockiert sein. Ein fehlender Ping allein beweist keinen Dienstausfall.
