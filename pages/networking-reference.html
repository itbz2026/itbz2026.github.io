Networking – Erweiterte Referenz

Systematisch sortierte Befehle, Optionen, Praxisbeispiele und Diagnose. Platzhalter wie HOST, USER, SERVICE und IP an die eigene Umgebung anpassen.

Wichtiger Hinweis: Befehle und Optionen hängen von Betriebssystem, Version, installierten Modulen und Berechtigungen ab. Vor produktiven Änderungen Herstellerdokumentation, Testumgebung, Backup und Rollback prüfen. Beispiele sind Vorlagen, keine universellen Produktionskonfigurationen.
01 · Referenz

IPv4-Subnetting und CIDR

CIDR-Präfix bestimmt Netz- und Hostanteil. Planung umfasst Netzadresse, Broadcast, nutzbare Hosts und reservierte Infrastrukturadressen.

# Beispielnetz: 192.0.2.0/24
# /24 = 255.255.255.0, 256 Adressen, klassisch 254 Hostadressen
# /26 = 255.255.255.192, 64 Adressen je Subnetz
# /30 = 255.255.255.252, 4 Adressen, klassisch 2 Hosts

Parameter und Hinweise: /31 wird auf Punkt-zu-Punkt-Verbindungen unterstützt; /32 bezeichnet eine einzelne Hostroute. IPv6 kennt kein Broadcast.

02 · Referenz

IPv6-Grundlagen

IPv6 verwendet 128-Bit-Adressen, Präfixe, Link-Local-Adressen und Neighbor Discovery. SLAAC und DHCPv6 können je nach Netzdesign eingesetzt werden.

ipconfig /all
ping -6 2001:db8::1
route print -6
# Linux
ip -6 addr
ip -6 route
ip -6 neigh

Parameter und Hinweise: 2001:db8::/32 ist für Dokumentationsbeispiele reserviert. Link-Local-Adressen beginnen mit fe80::/10 und sind nur auf dem lokalen Link gültig.

03 · Referenz

DNS-Diagnose

DNS arbeitet typischerweise über UDP/53, bei bestimmten Antworten und Transfers auch TCP/53. Recordtypen gezielt abfragen.

nslookup -type=MX example.com
nslookup -type=SRV _ldap._tcp.example.local
Resolve-DnsName example.com -Type A
Resolve-DnsName example.com -Type AAAA
dig +trace example.com
dig @192.0.2.53 example.com

Parameter und Hinweise: A=IPv4, AAAA=IPv6, CNAME=Alias, MX=Mailserver, PTR=Reverse Lookup, TXT=Text, SRV=Dienstlokalisierung.

04 · Referenz

DHCP DORA und Relay

DHCPv4-Lease durchläuft Discover, Offer, Request, Acknowledge. Relay-Agent leitet Broadcast-Anfragen über Router zu DHCP-Servern weiter.

ipconfig /release
ipconfig /renew
ipconfig /all
# Linux
sudo dhclient -v -r eth0
sudo dhclient -v eth0

Parameter und Hinweise: DHCP-Optionen umfassen unter anderem Router (003), DNS (006), DNS-Suffix (015). DHCP Snooping schützt Layer-2-Netze gegen unerlaubte DHCP-Server.

05 · Referenz

TCP, UDP und Ports

TCP bietet verbindungsorientierte, zuverlässige Übertragung; UDP ist verbindungslos und hat geringeren Protokollaufwand. Portnummern identifizieren Anwendungen.

Test-NetConnection server.example.com -Port 443
Get-NetTCPConnection -State Listen
ss -tulpn
nc -vz server.example.com 22
curl -I https://example.com

Parameter und Hinweise: Ein offener TCP-Port beweist nicht, dass die Anwendung korrekt funktioniert. TLS, Authentifizierung und Applikationslogs separat prüfen.

06 · Referenz

Routing und Default Gateway

Router leiten Pakete anhand der Routingtabelle weiter. Longest Prefix Match wählt die spezifischste passende Route.

route print
Get-NetRoute
ip route
ip route get 1.1.1.1
tracert 192.0.2.1
traceroute 192.0.2.1

Parameter und Hinweise: Default Route ist 0.0.0.0/0 für IPv4 und ::/0 für IPv6. Statische Routen benötigen korrekten Next Hop oder Ausgangsinterface.

07 · Referenz

NAT und PAT

NAT verändert IP-Adressen; PAT übersetzt zusätzlich Ports und ermöglicht mehreren internen Hosts eine öffentliche Adresse. NAT ersetzt keine Firewall.

# Cisco IOS Beispiel (Platzhalter):
show ip nat translations
show ip nat statistics
# Linux Status prüfen
nft list ruleset
# Windows NAT (Host/Hyper-V Szenario)
Get-NetNat

Parameter und Hinweise: NAT-Regeln sind plattformabhängig. Vor Änderungen Inside/Outside-Zonen, ACLs, Rückroute und Portweiterleitungen dokumentieren.

08 · Referenz

WLAN-Grundlagen

WLAN nutzt 2,4-, 5- und 6-GHz-Bänder abhängig von Region und Hardware. SSID, Authentifizierung, Kanalplanung und Roaming beeinflussen Qualität.

netsh wlan show interfaces
netsh wlan show networks mode=bssid
# Linux
nmcli device wifi list
iw dev

Parameter und Hinweise: WPA3 bevorzugen, WPS vermeiden und Managementzugriff vom Clientnetz trennen. 6 GHz setzt kompatible Clients und passende Sicherheitskonfiguration voraus.

09 · Referenz

MTU, VLAN und Trunk

MTU beeinflusst maximale Paketgröße. VLANs trennen Layer-2-Broadcast-Domänen; Trunks transportieren mehrere VLANs zwischen Netzwerkgeräten.

ping -f -l 1472 192.0.2.1
# Cisco IOS
show vlan brief
show interfaces trunk
show interfaces switchport
# Linux
ip -d link show

Parameter und Hinweise: Ethernet-MTU 1500 ist üblich, aber nicht universell. VLAN-ID, Native VLAN und erlaubte VLAN-Liste an beiden Trunk-Enden abstimmen.

10 · Referenz

Packet Capture

Paketmitschnitte helfen bei DNS-, TCP-, DHCP- und TLS-Problemen. Capture-Filter klein halten und Datenschutz beachten.

# Linux
tcpdump -ni eth0 host 192.0.2.10
sudo tcpdump -ni eth0 port 53
# Windows
pktmon start --capture --pkt-size 0
pktmon stop
pktmon etl2pcap PktMon.etl --out capture.pcapng

Parameter und Hinweise: Mitschnitte können personenbezogene Daten und Zugangsinformationen enthalten. Nur autorisiert erfassen, sicher speichern und nach Analyse löschen.
