Docker

Container, Images, Docker Compose und Betrieb

Architektur

Image, Container und Registry

  • Image: schreibgeschützte Vorlage aus Layern.
  • Container: Instanz eines Images mit eigener beschreibbarer Ebene.
  • Registry: speichert und verteilt Images.
  • Volume: persistenter Speicher unabhängig vom Container-Lebenszyklus.
  • Compose: beschreibt Services, Netzwerke und Volumes deklarativ in YAML.

Container teilen den Kernel des Hosts. Sie sind keine vollständigen virtuellen Maschinen.

Befehle

Container im Alltag

docker version
docker info
docker ps
docker ps -a
docker images
docker pull IMAGE:TAG
docker run -d --name web -p 8080:80 nginx
docker logs -f web
docker exec -it web sh
docker stop web
docker start web
docker rm web

Image-Tags bewusst wählen und Versionen dokumentieren. Vermeide unbeabsichtigte Updates durch unkontrollierte Tags.

Volumes

Persistente Daten speichern

docker volume create appdata
docker volume ls
docker volume inspect appdata
docker run -d --name app -v appdata:/var/lib/app IMAGE:TAG
docker inspect app
Container löschen entfernt nicht automatisch Named Volumes. Umgekehrt kann docker compose down -v Volumes löschen. Vor solchen Aktionen Daten sichern.
Netzwerke

Container-Netzwerke

docker network ls
docker network create app-net
docker network inspect app-net
docker run -d --network app-net --name web nginx
docker network connect app-net web
docker network disconnect app-net web
  • Bridge: häufig für Kommunikation auf einem einzelnen Host.
  • Host: Container nutzt den Netzwerk-Namespace des Hosts.
  • None: kein normales externes Netzwerk.

In benutzerdefinierten Bridge-Netzen können Container einander in der Regel über Servicenamen erreichen.

Docker Compose

Beispiel einer Compose-Datei

services:
  web:
    image: nginx:stable
    ports:
      - "8080:80"
    restart: unless-stopped
    volumes:
      - webdata:/usr/share/nginx/html:ro

volumes:
  webdata:
docker compose config
docker compose up -d
docker compose ps
docker compose logs -f
docker compose pull
docker compose down

Compose-Befehle im Verzeichnis der Compose-Datei ausführen oder den Pfad mit -f angeben.

Logs & Diagnose

Container untersuchen

docker logs --tail 100 CONTAINER
docker inspect CONTAINER
docker stats
docker top CONTAINER
docker events
docker system df
docker port CONTAINER

Bei Startfehlern zuerst Exit-Code, Logs, Mounts, Umgebungsvariablen, Portkonflikte und Dateiberechtigungen prüfen.

Updates

Images kontrolliert aktualisieren

  1. Release Notes und Kompatibilität prüfen.
  2. Persistente Daten und Konfiguration sichern.
  3. Neues Image gezielt pullen.
  4. Service mit dem neuen Image neu erstellen.
  5. Healthchecks, Logs und Anwendung testen.
  6. Rollback-Möglichkeit und Backup aufbewahren.
Ein Image-Update ist kein Datenbank-Upgrade. Bei Anwendungen mit Datenbankschema Hersteller-Migrationsschritte beachten.
Sicherheit

Docker Hardening

  • Images aus vertrauenswürdigen Quellen beziehen und aktualisieren.
  • Container möglichst als Nicht-root betreiben.
  • Keine unnötigen Ports veröffentlichen.
  • Secrets nicht in Images, Git-Repositories oder Klartext-Compose-Dateien speichern.
  • Capabilities reduzieren und privilegierte Container vermeiden.
  • Docker-Socket nicht unbedacht in Container mounten.
  • Ressourcenlimits, Read-only-Dateisysteme und Healthchecks nutzen, wo passend.
  • Zugriff auf Docker-Daemon und Gruppe docker streng kontrollieren: sie gewährt weitreichende Host-Rechte.
