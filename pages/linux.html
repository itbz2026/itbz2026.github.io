Benutzer & Rechte

Konten, Gruppen und Dateirechte

id USER
getent passwd USER
sudo adduser USER
sudo usermod -aG sudo USER
groups USER
ls -l FILE
chmod 640 FILE
chown USER:GROUP FILE
umask

Rechte: r = lesen, w = schreiben, x = ausführen beziehungsweise Verzeichnis betreten. Numerisch: 4 = Lesen, 2 = Schreiben, 1 = Ausführen. 640 bedeutet Eigentümer lesen/schreiben, Gruppe lesen, andere keine Rechte.

chmod -R 777 ist keine sichere Standardlösung. Rechte gezielt auf Eigentümer, Gruppe und notwendige Zugriffe begrenzen.
systemd

Dienste und Logs verwalten

systemctl status ssh
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl restart ssh
sudo systemctl enable ssh
sudo systemctl disable ssh
systemctl list-units --type=service
journalctl -u ssh
journalctl -p err -b
journalctl -f

enable aktiviert den automatischen Start beim Booten; start startet den Dienst sofort. Das sind unterschiedliche Aktionen.

SSH

SSH sicher betreiben

ssh-keygen -t ed25519
ssh-copy-id USER@SERVER
sudo sshd -t
sudo systemctl reload ssh
  • Schlüsselbasierte Anmeldung bevorzugen.
  • Root-Login nur nach geprüftem Alternativzugang deaktivieren.
  • SSH-Zugriff per Firewall auf notwendige Netze begrenzen.
  • Private Schlüssel schützen und bei Verdacht rotieren.
Vor Änderungen an sshd eine bestehende Sitzung offen lassen und zweiten Login testen, damit du dich nicht aussperrst.

Firewall

Firewall mit UFW

sudo ufw status verbose
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
sudo ufw enable
Vor Aktivierung die SSH-Regel passend zum Admin-Netz anlegen. Firewallregeln auf benötigte Dienste beschränken.
