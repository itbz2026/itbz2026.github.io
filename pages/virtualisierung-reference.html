Virtualisierung – Erweiterte Referenz

Systematisch sortierte Befehle, Optionen, Praxisbeispiele und Diagnose. Platzhalter wie HOST, USER, SERVICE und IP an die eigene Umgebung anpassen.

Wichtiger Hinweis: Befehle und Optionen hängen von Betriebssystem, Version, installierten Modulen und Berechtigungen ab. Vor produktiven Änderungen Herstellerdokumentation, Testumgebung, Backup und Rollback prüfen. Beispiele sind Vorlagen, keine universellen Produktionskonfigurationen.
01 · Referenz

Hypervisor-Konzepte

Typ-1-Hypervisor läuft direkt auf Hardware; Typ-2-Hypervisor als Anwendung auf einem Hostbetriebssystem. CPU-Virtualisierung, RAM und Storage sind zentrale Ressourcen.

# Host-Checks
# Windows
systeminfo
Get-ComputerInfo | Select-Object HyperVisorPresent
# Linux
lscpu | grep -E 'Virtualization|Model name'
lsmod | grep kvm

Parameter und Hinweise: VM-Kompatibilität hängt von CPU-Erweiterungen, Firmware, Hypervisor-Version und Gastbetriebssystem ab.

02 · Referenz

VMware ESXi – Hostdiagnose

ESXi verwaltet VMs, Datastores, virtuelle Switches und VMkernel-Netze. ESXCLI-Befehle sind versions- und Berechtigungsabhängig.

esxcli system version get
esxcli hardware platform get
esxcli network nic list
esxcli storage filesystem list
esxcli vm process list

Parameter und Hinweise: ESXi Shell/SSH nur für Administration aktivieren und danach wieder deaktivieren. Vor Storage- oder Netzwerkänderungen Out-of-band-Zugang sicherstellen.

03 · Referenz

VMware – VM und Netzwerk

Portgroups, vSwitches, VLAN-IDs und Uplinks müssen mit der physischen Switchkonfiguration übereinstimmen.

esxcli network vswitch standard list
esxcli network vswitch standard portgroup list
esxcli network ip interface list
esxcli network ip route ipv4 list

Parameter und Hinweise: VLAN-ID 0/None, 1–4094 und Trunking-Verhalten unterscheiden sich je nach Portgroup- und Switchdesign.

04 · Referenz

Proxmox VE – Status und Cluster

Proxmox VE nutzt KVM/QEMU für VMs und LXC für Container. Cluster-Quorum und Storage-Verfügbarkeit vor Änderungen prüfen.

pveversion -v
pvecm status
pvesh get /nodes
qm list
pct list
pvesm status

Parameter und Hinweise: Cluster ohne Quorum kann Schreiboperationen blockieren. Keine corosync-/Quorum-Änderung ohne Kenntnis der Clusterarchitektur.

05 · Referenz

Proxmox – VM Verwaltung

qm verwaltet QEMU-VMs; pct verwaltet LXC-Container. Konfiguration und Task-Logs vor Änderungen prüfen.

qm config 100
qm status 100
qm start 100
qm shutdown 100
qm snapshot 100 pre-change
pct config 101
pct status 101

Parameter und Hinweise: VMID und Storage vor Befehlen prüfen. Snapshots sind kein Ersatz für unabhängige Backups.

06 · Referenz

Hyper-V – PowerShell

Hyper-V-Cmdlets verwalten VMs, virtuelle Switches, virtuelle Festplatten und Checkpoints.

Get-VM
Get-VMNetworkAdapter -VMName 'APP01'
Get-VMSwitch
Get-VHD -Path 'D:\VMs\APP01.vhdx'
Checkpoint-VM -Name 'APP01' -SnapshotName 'BeforeUpdate'

Parameter und Hinweise: Checkpoints erhöhen Storagebedarf und sind keine Backupstrategie. Produktions-Checkpoints und App-Konsistenz passend planen.

07 · Referenz

Virtuelle Netzwerke

Bridged/External verbindet VMs mit physischem Netz; NAT teilt Host-Uplink; Host-only/Private isoliert je nach Plattform. VLAN und MTU müssen abgestimmt sein.

# Hyper-V
Get-VMSwitch
Get-VMNetworkAdapterVlan -VMName 'APP01'
# Proxmox
cat /etc/network/interfaces
bridge link
ip -d link show

Parameter und Hinweise: Änderungen an Management-vSwitch oder Bridge können den Hostzugriff verlieren. Wartungsfenster und lokale Konsole vorsehen.

08 · Referenz

Snapshots und Backups

Snapshots/Checkpoints sind kurzfristige Rücksprungpunkte. Backup muss unabhängig, versioniert und wiederherstellbar sein.

# Proxmox
pvesm status
# VMware
vim-cmd vmsvc/getallvms
# Hyper-V
Get-VMSnapshot -VMName 'APP01'

Parameter und Hinweise: Lange Snapshotketten belasten Storage und Performance. Snapshots nach erfolgreicher Änderung kontrolliert konsolidieren/löschen.

09 · Referenz

Kapazitätsplanung und Performance

CPU Ready/Co-Stop, Memory Ballooning/Swapping, Storage-Latenz und Netzwerkdrops getrennt betrachten.

# ESXi
esxtop
# Proxmox/Linux
top
free -h
iostat -xz 1 5
# Hyper-V
Get-Counter '\Hyper-V Hypervisor Virtual Processor(*)\% Total Run Time'

Parameter und Hinweise: Ein einzelner hoher Hostwert erklärt nicht automatisch eine langsame VM. Zeitfenster, Gastmetriken und Storagepfad korrelieren.
