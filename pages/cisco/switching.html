1. Grundlagen und CLI

Basis

show version und show inventory

Zweck: Modell, IOS-/IOS-XE-Version, Laufzeit, Seriennummern und Hardware ermitteln.

Syntax: show version, show inventory.

show version
show inventory
show platform
show switch

Praxis: Vor Änderungen Modell, Softwarestand, Stack-Mitglieder und Hardware dokumentieren. show switch ist für Stack-fähige Plattformen gedacht.

Basis

CLI-Modi, Hilfe und Abkürzungen

Zweck: Navigation zwischen User EXEC, Privileged EXEC, Global Config und Interface Config.

Befehle: enable, configure terminal, interface, exit, end, do, ?.

enable
configure terminal
interface gigabitEthernet 1/0/1
description USER-PORT
do show interfaces status
end
show ?
configure terminal
interface ?
end

Hinweis: do führt EXEC-Befehle aus dem Konfigurationsmodus aus. ? zeigt kontextabhängige Syntax.

Basis

Running- und Startup-Configuration

Zweck: Vergleicht aktive Konfiguration im RAM mit der gespeicherten Startkonfiguration.

Syntax: show running-config, show startup-config.

show running-config
show startup-config
show running-config | section interface
show running-config | include hostname
copy running-config startup-config

Achtung: Den letzten Befehl erst nach erfolgreicher Prüfung ausführen. Er speichert die laufende Konfiguration als Startkonfiguration.

2. Interfaces und Port-Grundlagen

Interface

show interfaces status und description

Zweck: Zeigt Linkstatus, VLAN, Duplex, Geschwindigkeit und Portbeschreibung.

Syntax: show interfaces status.

show interfaces status
show interfaces description
show ip interface brief
show interfaces gigabitEthernet 1/0/10

Auswertung: connected zeigt einen aktiven Link; notconnect meist fehlenden Link; err-disabled eine Schutzabschaltung. Werte je Plattform interpretieren.

Interface

interface und interface range

Zweck: Wählt einen einzelnen Port oder mehrere Ports aus.

Syntax: interface TYPE SLOT/PORT oder interface range TYPE FIRST-LAST.

configure terminal
interface gigabitEthernet 1/0/10
 description PC-FINANCE
 no shutdown
exit
interface range gigabitEthernet 1/0/1-24
 description USER-ACCESS-PORTS
end
show interfaces description

Achtung: Interface-Namen unterscheiden sich zwischen Modellen. Range nur nutzen, wenn alle Ports dieselbe Konfiguration erhalten sollen.

Interface

shutdown, no shutdown, speed und duplex

Zweck: Administratives Aktivieren/Deaktivieren und Aushandlung von Geschwindigkeit/Duplex.

Syntax: shutdown, no shutdown, speed auto, duplex auto; Optionen hardwareabhängig.

interface gigabitEthernet 1/0/10
shutdown
no shutdown
speed auto
duplex auto
end
show interfaces gi1/0/10
show interfaces status

Best Practice: Auto-Negotiation auf modernen Ports bevorzugen, sofern das Design nichts anderes verlangt. Vor shutdown prüfen, ob ein produktiver Link betroffen ist.

Interface

Interface-Fehlerzähler und Transceiver

Zweck: Findet CRC/FCS, Input-/Output-Errors, Drops und physische Probleme.

show interfaces gi1/0/10
show interfaces counters errors
show interfaces counters
show interfaces transceiver detail
show logging

Auswertung: CRC/FCS deutet oft auf Kabel, Stecker oder Optik; Drops können Überlastung/Queue-Probleme anzeigen. Transceiver-Befehle sind modellabhängig.

3. VLANs und Access-Ports

VLAN

VLAN erstellen und benennen

Zweck: Erstellt eine eigene Layer-2-Broadcast-Domäne.

Syntax: vlan VLAN-ID, name VLAN-NAME.

Parameter: VLAN-ID meist 1–4094; nutzbarer Bereich hängt von Plattform und VTP-Modus ab.

configure terminal
vlan 10
 name CLIENTS
vlan 20
 name SERVERS
vlan 30
 name VOICE
end
show vlan brief
show vlan id 10

Praxis: Nummern und Namen nach einem einheitlichen Schema dokumentieren.

VLAN

Access-Port zuweisen

Zweck: Ordnet einen Endgeräte-Port einem untagged VLAN zu.

Syntax: switchport mode access, switchport access vlan VLAN-ID.

configure terminal
interface gigabitEthernet 1/0/10
 description CLIENT-PC
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 no shutdown
end
show interfaces gi1/0/10 switchport
show vlan brief

Prüfen: Operational Mode muss Access und Access Mode VLAN muss 10 anzeigen. PortFast nur auf Endgeräte-Ports.

VLAN

VLAN ändern, löschen und Interface zurücksetzen

Zweck: Ändert die Port-Zuordnung oder entfernt ein nicht mehr benötigtes VLAN.

interface gigabitEthernet 1/0/10
 switchport access vlan 20
exit
no vlan 30
default interface gigabitEthernet 1/0/10
show vlan brief
show interfaces status

Achtung: no vlan nur ausführen, wenn VLAN nicht mehr verwendet wird. default interface entfernt die gesamte Portkonfiguration und kann Dienste unterbrechen.

VLAN

VLAN- und Port-Zuordnung prüfen

Zweck: Prüft VLAN-Status, Mitgliedschaft und Betriebsmodus eines Ports.

show vlan brief
show vlan id 10
show interfaces gi1/0/10 switchport
show interfaces status
show mac address-table vlan 10

Fehlerbild: VLAN fehlt, Port gehört falschem VLAN oder MAC wird im erwarteten VLAN nicht gelernt.

4. Voice VLAN

Voice VLAN

IP-Telefon und PC am selben Switchport

Zweck: Trennt Sprachverkehr des IP-Telefons vom Datenverkehr des angeschlossenen PCs.

Syntax: switchport voice vlan VLAN-ID.

vlan 10
 name DATA
vlan 30
 name VOICE
interface gigabitEthernet 1/0/15
 description PHONE-AND-PC
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 30
 spanning-tree portfast
end
show interfaces gi1/0/15 switchport
show mac address-table interface gi1/0/15

Hinweis: Telefon, LLDP/CDP, DHCP-Optionen, QoS und Call-Control müssen zusätzlich passend eingerichtet sein.

5. 802.1Q Trunking und DTP

Trunk

802.1Q Trunk konfigurieren

Zweck: Transportiert mehrere VLANs getaggt zwischen Switches oder zu Router/Server.

Syntax: switchport mode trunk.

interface gigabitEthernet 1/0/48
 description UPLINK-TO-SW2
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 switchport trunk native vlan 999
 no shutdown
end
show interfaces trunk
show interfaces gi1/0/48 switchport

Parameter: Allowed VLAN begrenzt die transportierten VLANs; Native VLAN transportiert untagged Frames. VLAN 999 ist ein Beispiel und muss auf beiden Seiten übereinstimmen.

Hinweis: Viele moderne Catalyst-Plattformen verwenden 802.1Q fest; ein Encapsulation-Befehl ist dort nicht nötig/verfügbar.

Trunk

Allowed VLANs setzen, ergänzen und entfernen

Syntax: switchport trunk allowed vlan VLAN-LIST, add, remove, all, none.

interface gi1/0/48
 switchport trunk allowed vlan 10,20
 switchport trunk allowed vlan add 30
 switchport trunk allowed vlan remove 20
show interfaces trunk

Achtung: Ohne add ersetzt die Liste die bisherige Konfiguration. Remote-Uplinks können dadurch Management oder VLANs verlieren.

Trunk

Native VLAN konfigurieren und prüfen

Zweck: Legt fest, welchem VLAN untagged Frames auf einem Trunk zugeordnet werden.

interface gi1/0/48
 switchport trunk native vlan 999
end
show interfaces trunk
show interfaces gi1/0/48 switchport

Best Practice: Native VLAN auf beiden Seiten identisch und möglichst ungenutzt halten. Native VLAN nicht mit Management VLAN verwechseln.

DTP

DTP und switchport nonegotiate

Zweck: DTP handelt Trunking dynamisch aus; auf fest definierten Trunks kann es deaktiviert werden.

interface gi1/0/48
 switchport mode trunk
 switchport nonegotiate
end
show interfaces gi1/0/48 switchport

Hinweis: Gegenstelle muss manuell als Trunk konfiguriert sein. Dynamic Auto/Desirable sind plattformabhängig; Access-Ports nicht dynamisch verhandeln lassen.

6. VTP v1, v2 und v3

VTP

VTP-Versionen und Modi verstehen

Zweck: Verteilt VLAN-Datenbankinformationen innerhalb einer VTP-Domain über Trunk-Links.

VersionMerkmale
VTP v1Grundlegende VLAN-Verteilung.
VTP v2Zusätzliche Funktionen, u. a. Token-Ring-Unterstützung und Konsistenzprüfungen.
VTP v3Primary-Server-Konzept, erweiterte VLAN-Funktionen und Verbesserungen; Plattformunterstützung prüfen.

Modi: Server verwaltet/verteilt VLAN-Datenbank; Client übernimmt; Transparent verwaltet VLANs lokal und leitet Advertisements weiter; Off ist releaseabhängig.

VTP

VTP-Status und Revision prüfen

show vtp status
show vtp counters
show vlan brief

Prüfen: Domain, Version, Modus, Configuration Revision und Primary-Server-Informationen. Gebrauchte Switches vor Anschluss isolieren und Revision prüfen.

VTP

VTP v3 Server – Laborbeispiel

configure terminal
vtp domain CAMPUS-LAB
vtp version 3
vtp mode server
vtp password CHANGE-THIS
end
vtp primary vlan
show vtp status

Parameter: Domain und Passwort müssen im geplanten Design übereinstimmen. Primary-Rolle nur bewusst auf dem vorgesehenen Switch vergeben.

Warnung: VTP kann VLAN-Datenbanken verändern. In vielen Netzen wird transparent/off und lokale VLAN-Verwaltung bevorzugt.

VTP

VTP Client und Transparent

configure terminal
vtp domain CAMPUS-LAB
vtp version 3
vtp mode client
end
show vtp status

configure terminal
vtp mode transparent
end
show vtp status

Hinweis: VTP v3-Verhalten und Syntax unterscheiden sich von v1/v2. Vor Einsatz Plattform- und Release-Dokumentation prüfen.

7. Spanning Tree – STP, RSTP, MST und Schutz

STP

STP-Modi und Status prüfen

Protokolle: IEEE STP 802.1D, RSTP 802.1w, MST 802.1s, Cisco PVST+ und Rapid-PVST+.

show spanning-tree
show spanning-tree summary
show spanning-tree vlan 10
show spanning-tree root
show spanning-tree blockedports

Auswertung: Root Bridge, Root Port, Designated/Alternate Ports, Forwarding/Blocking und Topology Changes kontrollieren.

STP

Rapid-PVST+ konfigurieren

configure terminal
spanning-tree mode rapid-pvst
end
show spanning-tree summary

Hinweis: Moduswechsel kann eine Neuberechnung auslösen. Alle Switches und Interoperabilität im Layer-2-Netz berücksichtigen.

STP

Root Bridge Primary und Secondary

Zweck: Bestimmt den bevorzugten Root-Switch je VLAN.

! Core 1
spanning-tree vlan 10 root primary
spanning-tree vlan 20 root primary

! Core 2 – Backup
spanning-tree vlan 10 root secondary
spanning-tree vlan 20 root secondary

show spanning-tree root
show spanning-tree vlan 10

Hinweis: Makrobefehle passen die Bridge-Priority an. Anschließend tatsächliche Root-ID prüfen.

STP

PortFast und BPDU Guard

Zweck: PortFast beschleunigt Edge-Ports; BPDU Guard schützt vor unerwarteten BPDUs.

interface gi1/0/10
 switchport mode access
 spanning-tree portfast
 spanning-tree bpduguard enable
end
show spanning-tree interface gi1/0/10 detail

Global: spanning-tree portfast default und spanning-tree portfast bpduguard default nur bei sauber definierten Edge-Ports einsetzen. Niemals pauschal auf Switch-Uplinks.

STP

Root Guard, Loop Guard und BPDU Filter

Zweck: Zusätzliche Schutzmechanismen gegen unerwartete Root-Wechsel, unidirektionale Fehler und unerwünschte BPDU-Verarbeitung.

interface gi1/0/48
 spanning-tree guard root
interface gi1/0/47
 spanning-tree guard loop
show spanning-tree inconsistentports
show spanning-tree summary

Warnung: BPDU Filter kann STP-Schutz aushebeln und Layer-2-Schleifen verursachen. Nur nach Designvorgabe einsetzen.

STP

STP Kosten und Port-Priorität

interface gi1/0/48
 spanning-tree vlan 10 cost 20000
 spanning-tree vlan 10 port-priority 64
end
show spanning-tree vlan 10

Zweck: Beeinflusst Pfadauswahl. Wertebereiche und Kostenmodell hängen von Plattform und STP-Modus ab.

MST

MST Region und VLAN-Mapping

Zweck: Gruppiert VLANs in MST-Instanzen und reduziert die Zahl der STP-Instanzen.

spanning-tree mode mst
spanning-tree mst configuration
 name CAMPUS
 revision 1
 instance 1 vlan 10,20
 instance 2 vlan 30,40
 exit
show spanning-tree mst configuration
show spanning-tree mst

Achtung: Region Name, Revision und VLAN-Mapping müssen innerhalb einer MST-Region übereinstimmen.

8. EtherChannel, LACP und PAgP

LACP

LACP Port-Channel konfigurieren

Zweck: Bündelt mehrere physische Links nach IEEE 802.1AX.

Syntax: channel-group GROUP mode {active|passive}.

Parameter: Active initiiert, Passive antwortet. Passive/Passive bildet keinen Channel.

interface range gi1/0/47-48
 description LACP-MEMBERS
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 channel-group 1 mode active
 no shutdown
interface port-channel 1
 description UPLINK-TO-SW2
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 no shutdown
end
show etherchannel summary
show lacp neighbor
show interfaces port-channel 1

Wichtig: Member müssen kompatible VLAN-, Trunk-, Speed-, Duplex- und Layer-Modi haben. Syntax/Verhalten modellabhängig.

PAgP

PAgP Port-Channel konfigurieren

Zweck: Cisco-proprietäre EtherChannel-Aushandlung.

Syntax: channel-group GROUP mode {desirable|auto}. Desirable initiiert; Auto wartet. Auto/Auto bildet keinen Channel.

interface range gi1/0/45-46
 channel-group 2 mode desirable
interface port-channel 2
 switchport mode trunk
 switchport trunk allowed vlan 10,20
show etherchannel summary
show pagp neighbor

Hinweis: LACP ist für neue herstellerübergreifende Designs meist vorzuziehen.

EtherChannel

EtherChannel prüfen und Fehler finden

show etherchannel summary
show etherchannel port-channel
show etherchannel detail
show lacp neighbor
show pagp neighbor
show interfaces port-channel 1

Typische Fehler: Unterschiedliche Allowed-/Native-VLANs, Access-/Trunk-Modus, Geschwindigkeit, Duplex, LACP-Modus oder Layer-2-/Layer-3-Konfiguration.

9. MAC, CDP, LLDP, UDLD und ARP

MAC

MAC Address Table

Zweck: Ordnet gelernte MAC-Adressen VLANs und Ports zu.

show mac address-table
show mac address-table dynamic
show mac address-table vlan 10
show mac address-table interface gi1/0/10
show mac address-table address aaaa.bbbb.cccc

Praxis: MAC eines Clients suchen und den zugehörigen Switchport finden. Syntax einzelner Filter kann plattformabhängig sein.

CDP

CDP Nachbarn anzeigen und verwalten

Zweck: Erkennt direkt verbundene Cisco-Geräte.

show cdp
show cdp neighbors
show cdp neighbors detail
show cdp interface
show cdp traffic
no cdp run
interface gi1/0/10
 no cdp enable

Sicherheit: CDP global oder auf untrusted Access-Ports deaktivieren, wenn nicht benötigt. CDP kann Geräteinformationen offenlegen.

LLDP

LLDP aktivieren und Nachbarn prüfen

Zweck: Herstellerneutrales Neighbor Discovery nach IEEE 802.1AB.

configure terminal
lldp run
interface gi1/0/10
 lldp transmit
 lldp receive
end
show lldp
show lldp neighbors
show lldp neighbors detail

Praxis: Hilfreich für IP-Telefone, Access Points und Multi-Vendor-Umgebungen. Port-Unterstützung prüfen.

UDLD

UDLD gegen unidirektionale Links

Zweck: Erkennt einseitige Verbindungen, die STP-/EtherChannel-Probleme verursachen können.

udld enable
interface gi1/0/48
 udld port aggressive
end
show udld
show udld neighbors

Achtung: Aggressive Mode kann Ports deaktivieren. Auf unterstützten Links nach Netzwerkstandard einsetzen; Syntax je Plattform prüfen.

ARP

ARP- und SVI-Informationen

Zweck: Prüft IPv4-Nachbarschaft und VLAN-Interface auf Layer-3-Switches.

show ip arp
show ip arp 192.168.10.25
show ip interface brief
show interfaces vlan 10
show ip route

Hinweis: Reine Layer-2-Switches führen nicht zwingend eine ARP-Tabelle für Transitverkehr.

10. Layer-2-Security

Port Security

Port Security – MAC-Adressen begrenzen

Zweck: Begrenzt gelernte MAC-Adressen auf einem unterstützten Access-Port.

interface gi1/0/10
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
end
show port-security
show port-security interface gi1/0/10
show port-security address

Violation: Protect verwirft still; Restrict verwirft und zählt/loggt; Shutdown setzt den Port typischerweise err-disabled. Verhalten modellabhängig.

DHCP Snooping

DHCP Snooping konfigurieren

Zweck: Blockiert DHCP-Serverantworten von untrusted Ports und erstellt Binding-Informationen.

ip dhcp snooping
ip dhcp snooping vlan 10,20
interface gi1/0/48
 description UPLINK-TO-DHCP
 ip dhcp snooping trust
interface range gi1/0/1-24
 ip dhcp snooping limit rate 15
end
show ip dhcp snooping
show ip dhcp snooping binding

Wichtig: Nur legitime DHCP-Uplinks trusten. Rate-Limit passend dimensionieren. EtherChannel-Trust nach Plattformvorgabe konfigurieren.

DAI

Dynamic ARP Inspection

Zweck: Validiert ARP anhand von DHCP-Snooping-Bindings oder ARP-ACLs.

ip arp inspection vlan 10,20
interface gi1/0/48
 ip arp inspection trust
end
show ip arp inspection
show ip arp inspection interfaces
show ip arp inspection statistics

Voraussetzung: DHCP-Bindings oder ARP-ACLs für statische Geräte. Erst im Lab prüfen – falsche Einstellungen können legitime ARP-Pakete blockieren.

IP Source Guard

IP Source Guard

Zweck: Filtert IP-Verkehr auf Access-Ports anhand von DHCP-Snooping-Bindings oder statischen Bindings.

interface gi1/0/10
 switchport mode access
 ip verify source
end
show ip verify source
show ip dhcp snooping binding

Achtung: Statische IP-Geräte wie Drucker und Server vor Aktivierung berücksichtigen. Syntax und Unterstützung prüfen.

802.1X

802.1X und Authentifizierungsstatus

Zweck: Authentifiziert kabelgebundene Clients über AAA/RADIUS.

show authentication sessions
show dot1x all
show aaa servers
show radius statistics

Praxis: Vor Rollout RADIUS/ISE, Zertifikate, MAB-Fallback, Host-Modus, Guest-/Critical-VLAN und Recovery-Zugriff planen. Vollständige Konfiguration ist releaseabhängig.

Storm Control

Storm Control konfigurieren

Zweck: Begrenzt Broadcast-, Multicast- und Unknown-Unicast-Verkehr.

interface gi1/0/10
 storm-control broadcast level 5.00
 storm-control multicast level 5.00
 storm-control action trap
end
show storm-control
show running-config interface gi1/0/10

Hinweis: Schwellenwerte anhand normaler Last dimensionieren; zu niedrige Werte können legitimen Verkehr beeinträchtigen.

11. Multicast und IGMP Snooping

IGMP

IGMP Snooping und Multicast-Gruppen

Zweck: Lernt Multicast-Mitgliedschaften und verhindert unnötiges Flooding an alle Ports.

show ip igmp snooping
show ip igmp snooping vlan 20
show ip igmp snooping groups
show ip igmp snooping mrouter
show ip igmp snooping querier

Hinweis: Querier, Multicast-Router-Port und IGMP-Version müssen zum Netzdesign passen.

IGMP

IGMP Snooping Querier

Zweck: Stellt in einem VLAN ohne externen Querier einen Querier bereit, wenn Plattform und Design dies unterstützen.

ip igmp snooping querier
ip igmp snooping querier address 192.0.2.1
show ip igmp snooping querier

Achtung: Syntax/Verfügbarkeit prüfen und keine unkoordinierten konkurrierenden Querier einrichten.

12. SPAN und RSPAN

SPAN

Local SPAN – Port spiegeln

Zweck: Kopiert Verkehr eines Quellports auf einen Analyseport.

configure terminal
monitor session 1 source interface gi1/0/10 both
monitor session 1 destination interface gi1/0/20
end
show monitor session 1
show monitor session all

Wichtig: Zielport ist für SPAN reserviert. Bei hoher Last können Pakete verloren gehen.

SPAN

SPAN entfernen und RSPAN

show monitor session all
configure terminal
no monitor session 1
end
show monitor session all

RSPAN: Transportiert gespiegelten Verkehr über ein dediziertes Remote-SPAN-VLAN. Konfiguration und Einschränkungen sind modellabhängig; RSPAN-VLAN nicht als Client-VLAN verwenden.

13. PoE – Power over Ethernet

Stromversorgung für Access Points, IP-Telefone, Kameras und andere Endgeräte über Ethernet.

PoE

PoE-Status und verfügbares Power-Budget prüfen

Zweck: Zeigt, welche Ports Endgeräte versorgen, welchen Standard bzw. Leistungstyp sie verwenden und wie viel Leistung verfügbar ist.

show power inline
show power inline detail
show power inline gi1/0/10
show environment power
show interfaces status

Auswertung: Prüfe Status, Device, Class, benötigte Leistung, verfügbare Leistung und Gesamtbudget. Die genaue Ausgabe und unterstützten Optionen unterscheiden sich nach Catalyst-Modell und IOS/IOS XE.

PoE

PoE auf einem Interface konfigurieren

Zweck: Steuert, ob ein unterstützter Switchport PoE bereitstellt. Die verfügbaren Modi sind plattformabhängig.

configure terminal
interface gigabitEthernet 1/0/10
 power inline auto
end
show power inline gi1/0/10

Hinweis: auto ist auf vielen Catalyst-Plattformen der Standard. Nur wenn die Plattform es unterstützt und das Design es verlangt, weitere Modi wie static oder never verwenden. Syntax vorab mit power inline ? prüfen.

Achtung: power inline never unterbricht die Stromversorgung am Port. Vorher prüfen, ob Telefon, Access Point oder Kamera darüber versorgt wird.
PoE

PoE-Fehler systematisch eingrenzen

Typische Ursachen: Power-Budget erschöpft, inkompatibles Endgerät/Kabel, PoE deaktiviert, falsche Verkabelung oder Hardware-/Portfehler.

show power inline
show power inline detail
show power inline gi1/0/10
show logging
show interfaces gi1/0/10
show inventory

Vorgehen: Switch-Gesamtbudget prüfen, betroffenen Port und Kabel testen, Endgerät an einem bekannten funktionierenden Port prüfen und Logs auf Überlast- oder Hardwaremeldungen untersuchen. PoE-Budget und PoE/PoE+/UPOE-Unterstützung sind modellabhängig.

14. QoS – Quality of Service

Verkehr erkennen, markieren und bei Überlast priorisieren. QoS-Syntax und Hardware-Verhalten sind stark plattformabhängig.

QoS

QoS-Grundlagen: Classification, Marking und Queuing

Classification: Ordnet Verkehr anhand von DSCP, CoS, ACL oder anderen Merkmalen einer Klasse zu. Marking: Setzt DSCP- oder CoS-Werte. Queuing/Scheduling: Bestimmt die Behandlung bei Auslastung. Policing/Shaping: Begrenzt oder glättet Datenraten.

FeldTypische Verwendung
DSCPLayer-3-Markierung im IP-Header
CoS / 802.1pLayer-2-Priorität im VLAN-Tag
Trust BoundaryLegt fest, ob eingehende Markierungen übernommen werden
QueueAusgangswarteschlange und Scheduling-Verhalten

Praxis: End-to-End-QoS planen. Markierungen nicht unkontrolliert übernehmen; Trust Boundary am Telefon, Access Point oder Uplink bewusst festlegen.

QoS

QoS-Status und Interface-Statistiken prüfen

show mls qos
show mls qos interface gi1/0/10
show policy-map
show policy-map interface gi1/0/10
show class-map
show interfaces gi1/0/10 counters
show platform hardware fed switch active qos queue stats interface gi1/0/10

Hinweis: Nicht jeder Befehl existiert auf jeder Plattform. show mls qos gehört zu älteren Catalyst-Generationen; neuere Catalyst- und IOS-XE-Plattformen verwenden andere QoS-Modelle und Plattformdiagnosen.

QoS

Auto-QoS für Cisco IP-Telefone – Beispiel

Zweck: Auto-QoS kann auf unterstützten Catalyst-Plattformen passende QoS-Richtlinien für erkannte Sprachgeräte erzeugen.

interface gigabitEthernet 1/0/10
 auto qos voip cisco-phone
end
show running-config interface gi1/0/10
show policy-map interface gi1/0/10

Wichtig: Die Auto-QoS-Befehle unterscheiden sich je nach Plattform und Softwarestand. Auf manchen Geräten lautet die Option beispielsweise auto qos trust oder die Konfiguration wird über andere Profile erzeugt. Vor dem Einsatz auto qos ? prüfen und generierte Konfiguration kontrollieren.

QoS

MQC – Class-Map und Policy-Map verstehen

Zweck: Modular QoS CLI (MQC) trennt Klassifizierung (class-map) von Aktionen (policy-map) und der Anwendung auf Interfaces (service-policy).

class-map match-any VOICE
 match dscp ef
!
policy-map EXAMPLE-QOS
 class VOICE
  set dscp ef
!
interface gigabitEthernet 1/0/10
 service-policy input EXAMPLE-QOS
Nur Syntaxbeispiel: Dieses generische MQC-Beispiel ist keine universell gültige Catalyst-Konfiguration. Unterstützte Match-/Action-Befehle, Richtlinienrichtung, Queue-Zuordnung und Hardware-Ressourcen müssen für das konkrete Modell und Release geprüft werden. Bestehende QoS-Policies nicht ohne Prüfung ersetzen.

15. IPv6 Switching und First-Hop

IPv6 auf Management-SVIs und Layer-3-Switches, Neighbor Discovery und grundlegende Diagnose.

IPv6

IPv6-Status und Neighbor Discovery prüfen

show ipv6 interface brief
show ipv6 interface vlan 10
show ipv6 neighbors
show ipv6 route
show ipv6 protocols

Zweck: Prüft IPv6-Adressen, Interface-Status, Neighbor Cache und Routing-Tabelle. IPv6 Neighbor Discovery übernimmt Funktionen, die bei IPv4 unter anderem ARP erfüllt.

IPv6

IPv6 auf einem SVI konfigurieren

Zweck: Weist einem VLAN-Interface eine IPv6-Adresse zu, z. B. als Gateway für ein VLAN.

configure terminal
vlan 10
 name CLIENTS
interface vlan 10
 description CLIENTS-IPV6-GATEWAY
 ipv6 address 2001:db8:10::1/64
 no shutdown
end
show ipv6 interface brief
show ipv6 interface vlan 10

Hinweis: 2001:db8::/32 ist für Dokumentationsbeispiele reserviert. Für produktive Netze den zugewiesenen globalen Präfix verwenden. Das SVI benötigt ein aktives VLAN und mindestens einen aktiven Layer-2-Port im VLAN.

IPv6

IPv6-Routing auf einem Layer-3-Switch aktivieren

Zweck: Aktiviert IPv6-Weiterleitung zwischen gerouteten Interfaces/SVIs, sofern Plattform und Lizenz dies unterstützen.

configure terminal
ipv6 unicast-routing
interface vlan 10
 ipv6 address 2001:db8:10::1/64
 no shutdown
interface vlan 20
 ipv6 address 2001:db8:20::1/64
 no shutdown
end
show ipv6 route
show ipv6 interface brief
Achtung: Das Aktivieren von IPv6-Routing verändert das Weiterleitungsverhalten. Vor Produktiveinsatz IPv6-Adressplan, Routing, ACLs, RA/ND-Verhalten und Sicherheitsrichtlinien planen.
IPv6

IPv6 Default Route und statische Routen

configure terminal
ipv6 route ::/0 2001:db8:10::fe
ipv6 route 2001:db8:30::/64 2001:db8:20::fe
end
show ipv6 route static
show ipv6 route

Parameter: ::/0 ist die IPv6-Default-Route. Next-Hop-Adressen und Präfixe sind Beispiele und müssen zum eigenen Adressplan passen.

IPv6

IPv6 First-Hop Security – RA Guard und DHCPv6 Guard

Zweck: Schutzmechanismen können unerwünschte Router Advertisements bzw. DHCPv6-Nachrichten auf Access-Ports blockieren.

show ipv6 neighbors
show ipv6 interface vlan 10
show running-config interface gi1/0/10

Wichtig: RA Guard und DHCPv6 Guard sind auf unterstützten Plattformen verfügbar, aber Syntax, Policy-Modell und Einschränkungen unterscheiden sich stark. Die konkrete Konfiguration muss aus dem Configuration Guide des Switch-Modells und Releases übernommen werden. Nicht ungeprüft auf Uplinks oder Router-Ports anwenden.

IPv6

IPv6-Troubleshooting

show ipv6 interface brief
show ipv6 interface vlan 10
show ipv6 neighbors
show ipv6 route
show logging

Reihenfolge: IPv6-Adresse/Präfix prüfen, SVI-Status und VLAN-Aktivität kontrollieren, Neighbor Discovery prüfen, Default Gateway/Router Advertisements untersuchen, Routing und IPv6-ACLs kontrollieren.

16. Management und Betrieb

Management

Management-SVI und Default Gateway

Zweck: Weist einem Management-VLAN eine IP-Adresse zu.

vlan 99
 name MANAGEMENT
interface vlan 99
 description SWITCH-MANAGEMENT
 ip address 192.168.99.10 255.255.255.0
 no shutdown
ip default-gateway 192.168.99.1
show ip interface brief
show interfaces vlan 99

Hinweis: VLAN muss aktiv und erreichbar sein. Bei Layer-3-Switches mit Routing wird die Default-Route statt ip default-gateway verwendet.

NTP / Syslog

NTP und Syslog konfigurieren

Zweck: Sorgt für korrekte Zeit und zentrale Protokollierung.

service timestamps log datetime msec localtime
ntp server 192.0.2.123
logging host 192.0.2.50
logging trap informational
show clock detail
show ntp status
show ntp associations
show logging

Hinweis: Beispieladressen ersetzen. NTP-Erreichbarkeit, VRF, Authentifizierung und Syslog-Severity nach Unternehmensstandard konfigurieren.

Backup

Konfiguration sichern und archivieren

Zweck: Speichert die Konfiguration und ermöglicht – wenn unterstützt – lokale Konfigurationsarchive.

copy running-config startup-config
show running-config
show startup-config
show archive

Praxis: Vorher externes Backup exportieren, Änderung testen, anschließend speichern. Archive-Funktionen und Speicherpfad sind plattformabhängig.

17. Troubleshooting – systematische Reihenfolge

Physisch → Interface → VLAN → Trunk → STP → MAC → Security → Gateway/Anwendung.

Troubleshooting

Port down, Fehler oder err-disabled

show interfaces status
show interfaces gi1/0/10
show interfaces counters errors
show errdisable detect
show errdisable recovery
show logging

Prüfen: Kabel/Optik, Gegenstelle, Admin-Status, Speed/Duplex, CRC, Err-disabled-Ursache. Erst Ursache beheben, dann gezielt shutdown/no shutdown.

Troubleshooting

Client erreicht Gateway nicht

show vlan brief
show interfaces gi1/0/10 switchport
show interfaces trunk
show mac address-table dynamic
show spanning-tree vlan 10
show ip interface brief
show ip arp

Reihenfolge: Client-IP/Maske/Gateway; Access-VLAN; Trunk-Allowlist; STP Forwarding; MAC-Learning; SVI/Gateway; ACL und Host-Firewall prüfen.

Troubleshooting

Trunk transportiert VLAN nicht

show interfaces trunk
show interfaces gi1/0/48 switchport
show vlan brief
show spanning-tree vlan 10
show vtp status

Ursachen: VLAN fehlt/inaktiv, Allowlist, Native-VLAN-Mismatch, Trunk nicht operational, STP blockiert oder VTP-Konflikt.

Troubleshooting

EtherChannel nicht gebündelt

show etherchannel summary
show etherchannel detail
show lacp neighbor
show interfaces port-channel 1
show interfaces status

Ursachen: LACP-Modus, falsche Member, VLAN-/Trunk-Mismatch, Speed/Duplex oder Layer-2-/Layer-3-Unterschied.

Troubleshooting

STP blockiert unerwartet

show spanning-tree
show spanning-tree vlan 10
show spanning-tree root
show spanning-tree inconsistentports
show spanning-tree detail

Prüfen: Root Bridge, Kosten, Port-Rolle, Guard-Funktionen und Topology Changes. STP niemals deaktivieren, um einen blockierten Port scheinbar zu reparieren.

Troubleshooting

DHCP Snooping oder DAI blockiert Clients

show ip dhcp snooping
show ip dhcp snooping binding
show ip arp inspection
show ip arp inspection statistics
show ip arp inspection interfaces
show logging

Prüfen: DHCP-Uplink trusted, VLAN aktiviert, Binding vorhanden, statische Geräte berücksichtigt und Rate-Limits passend.

Checkliste

Standard-Check vor und nach Änderungen

show version
show inventory
show running-config
show interfaces status
show vlan brief
show interfaces trunk
show spanning-tree summary
show etherchannel summary
show mac address-table dynamic
show logging

Praxis: Vorher-Ausgaben sichern, eine Änderung nach der anderen durchführen, Funktion testen, Nachher-Ausgaben vergleichen und erst danach speichern.

18. Err-disabled Ports und Port-Recovery

Troubleshooting

Err-disabled Ursache ermitteln

Ein Port kann durch Schutzfunktionen wie BPDU Guard, Port Security, UDLD oder Link-Flap Detection deaktiviert werden. Erst Ursache finden, dann den Port wieder aktivieren.

show interfaces status err-disabled
show interfaces status
show errdisable recovery
show logging | include ERR_DISABLE|BPDU|PSECURE|UDLD
show interfaces gi1/0/10
show port-security interface gi1/0/10
Verfügbare Filter und Detailbefehle unterscheiden sich je nach Catalyst-Modell und IOS/IOS XE Release. Logs und Interface-Details gemeinsam auswerten.
Troubleshooting

Port nach Fehlerbehebung reaktivieren

Nach Behebung der Ursache den betroffenen Port kontrolliert neu starten.

configure terminal
interface gi1/0/10
shutdown
no shutdown
end
show interfaces gi1/0/10
show interfaces status
Achtung: Nicht einfach wiederholt shutdown/no shutdown ausführen. Bei aktiver Schutzverletzung wird der Port erneut deaktiviert. Automatische Errdisable-Recovery nur gezielt und passend zur Fehlerursache konfigurieren.
