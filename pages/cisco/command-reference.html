IOS · IOS-XE · NX-OS · Catalyst 9800

Cisco Command Reference

Schnell nachschlagen: Zweck, Syntax, Parameter, Beispiel, Ausgabeprüfung und Hinweise zur Plattform. Suche nach Befehlen oder Stichwörtern.

Syntax-Legende: WORD = festes Schlüsselwort · <wert> = einzusetzender Wert · [OPTION] = optional · {A | B} = eine der Alternativen. Parameter und Verfügbarkeit können je nach Modell und Softwareversion abweichen. Vor Änderungen immer ? zur kontextbezogenen Hilfe verwenden.

Grundlegende Diagnosebefehle

Häufig benötigte Befehle für den täglichen Betrieb.

show running-config

Zweck: Zeigt die aktuell aktive Gerätekonfiguration im Arbeitsspeicher.

Plattform: Cisco IOS / IOS-XE; vergleichbare Befehle auf NX-OS.

Syntax: show running-config [ | include WORD ]

Parameter: | include WORD filtert die Ausgabe nach einer Zeichenfolge. Weitere Pipe-Filter wie begin oder section sind plattformabhängig.

show running-config
show running-config | include hostname
show running-config | section interface

Prüfen: Kontrolliere, ob die erwarteten Interfaces, VLANs und Routing-Einstellungen vorhanden sind.

Hinweis: Änderungen in der Running-Config sind nicht automatisch dauerhaft gespeichert.

show startup-config

Zweck: Zeigt die gespeicherte Konfiguration, die beim Neustart geladen wird.

Plattform: IOS / IOS-XE; Speichermechanismus auf anderen Plattformen prüfen.

Syntax: show startup-config

Parameter: Keine regulären Parameter.

show startup-config

Praxis: Mit show running-config vergleichen, wenn du prüfen möchtest, ob letzte Änderungen gespeichert wurden.

copy running-config startup-config

Zweck: Speichert die aktive Konfiguration als Startkonfiguration.

Plattform: IOS / IOS-XE; Syntax kann auf NX-OS abweichen.

Syntax: copy running-config startup-config

Parameter: Quelle = running-config; Ziel = startup-config.

copy running-config startup-config

Achtung: Erst nach erfolgreicher Prüfung speichern. Dadurch werden auch versehentliche Änderungen für den nächsten Neustart übernommen.

show version

Zweck: Zeigt Plattform, Softwareversion, Laufzeit und weitere Systeminformationen.

Plattform: IOS / IOS-XE; NX-OS besitzt ebenfalls show version, die Ausgabe unterscheidet sich.

Syntax: show version

Parameter: Keine regulären Parameter.

show version

Praxis: Vor einer Konfigurationsänderung Modell und Softwareversion erfassen.

show inventory

Zweck: Zeigt erkannte Hardware-Komponenten und Produktkennungen.

Plattform: Viele Catalyst IOS-XE-Geräte; Verfügbarkeit modellabhängig.

Syntax: show inventory

show inventory

Praxis: Hilfreich für Hardware-Dokumentation und Supportfälle.

show interfaces status

Zweck: Kompakte Übersicht über Switchports, Status, VLAN, Duplex und Geschwindigkeit.

Plattform: Viele Catalyst Switches; Router und andere Plattformen verwenden teils andere Varianten.

Syntax: show interfaces status

show interfaces status
show interfaces gigabitEthernet 1/0/1

Parameter: Ein Interface kann für die Detailansicht ergänzt werden; Interface-Namen und Nummerierung sind geräteabhängig.

show ip interface brief

Zweck: Schnelle Übersicht über IPv4-Adressen und den Status von Layer-3-Interfaces.

Plattform: IOS / IOS-XE; auf NX-OS je nach Feature und Version prüfen.

Syntax: show ip interface brief

show ip interface brief

Auswertung: up/up bedeutet, dass Interface und Line Protocol aktiv sind. administratively down weist meist auf shutdown hin.

show logging

Zweck: Zeigt lokale Systemmeldungen und Ereignisse.

Plattform: IOS / IOS-XE; Umfang und Filter unterscheiden sich.

Syntax: show logging

show logging

Praxis: Nach Link-Flaps, Port-Security-Verstößen oder Routing-Problemen prüfen.

Interfaces und Layer 2

Konfiguration und Kontrolle von Ports und VLANs.

interface

Zweck: Wechselt in den Konfigurationsmodus eines Interfaces.

Plattform: IOS / IOS-XE; Interface-Bezeichnungen unterscheiden sich nach Hardware.

Syntax: interface TYPE SLOT/PORT

Parameter: TYPE z. B. GigabitEthernet; SLOT/PORT ist die gerätespezifische Portnummer.

configure terminal
interface GigabitEthernet1/0/10
 description Uplink-to-SW2
 no shutdown

Hinweis: Vor Änderungen immer sicherstellen, dass du den richtigen Port ausgewählt hast.

switchport mode access

Zweck: Setzt einen Layer-2-Port auf Access-Modus für ein einzelnes Access-VLAN.

Plattform: Layer-2-fähige Catalyst Switchports; nicht auf jedem Router- oder L3-Port verfügbar.

Syntax: switchport mode access

Parameter: Keine. Das zugehörige VLAN wird separat mit switchport access vlan VLAN-ID gesetzt.

interface GigabitEthernet1/0/10
 switchport mode access
 switchport access vlan 20
 spanning-tree portfast

Prüfen: show interfaces switchport und show vlan brief.

switchport trunk allowed vlan

Zweck: Legt fest, welche VLANs über einen 802.1Q-Trunk transportiert werden.

Plattform: Unterstützte Catalyst Layer-2-Trunkports; Syntax und Trunk-Verhalten modellabhängig.

Syntax: switchport trunk allowed vlan { add | remove | except } VLAN-LIST

Parameter: add ergänzt VLANs; remove entfernt VLANs; except erlaubt alle außer der angegebenen Liste. Ohne diese Schlüsselwörter ersetzt eine neue Liste in der Regel die bisherige Liste.

interface GigabitEthernet1/0/48
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
! VLAN 40 ergänzen:
 switchport trunk allowed vlan add 40

Prüfen: show interfaces trunk. Achtung: Eine versehentlich ersetzte VLAN-Liste kann Verbindungen unterbrechen.

show vlan brief

Zweck: Zeigt VLANs und zugeordnete Access-Ports.

Plattform: Catalyst Layer-2-Switching; Ausgabe abhängig von VTP- und VLAN-Konfiguration.

Syntax: show vlan brief

show vlan brief
show vlan id 20

Parameter: id 20 zeigt ein bestimmtes VLAN, sofern unterstützt.

show mac address-table

Zweck: Zeigt gelernte MAC-Adressen und die zugehörigen VLANs/Ports.

Plattform: Catalyst IOS / IOS-XE; Syntax auf NX-OS ähnlich, aber nicht identisch.

Syntax: show mac address-table [ dynamic | static ] [ vlan VLAN-ID ]

Parameter: dynamic oder static filtert nach Eintragstyp; vlan VLAN-ID begrenzt die Anzeige auf ein VLAN.

show mac address-table
show mac address-table dynamic vlan 20

Routing und Redundanz

show ip route

Zweck: Zeigt die IPv4-Routingtabelle.

Plattform: IOS / IOS-XE; NX-OS unterstützt eigene Varianten.

Syntax: show ip route [ IP-ADDRESS | PROTOCOL ]

Parameter: Optional eine Ziel-IP oder ein Routingprotokoll, z. B. ospf oder eigrp, sofern unterstützt.

show ip route
show ip route 192.168.20.10
show ip route ospf

Auswertung: Achte auf Präfix, Next Hop, Ausgangsinterface und Administrative Distance.

show ip ospf neighbor

Zweck: Zeigt OSPF-Nachbarn und deren Adjazenzstatus.

Plattform: IOS / IOS-XE mit aktiviertem OSPF; Syntax kann je nach OSPF-Variante abweichen.

Syntax: show ip ospf neighbor [ detail ]

Parameter: detail zeigt zusätzliche Nachbarinformationen.

show ip ospf neighbor
show ip ospf neighbor detail

Prüfen: Bei fehlenden Nachbarn Area, Netzmaske, Hello/Dead-Timer, Authentifizierung und Layer-3-Erreichbarkeit kontrollieren.

standby

Zweck: Konfiguriert HSRP auf einem Layer-3-Interface.

Plattform: IOS / IOS-XE auf Geräten mit HSRP-Unterstützung; Feature- und Versionsabhängigkeit beachten.

Syntax: standby GROUP ip VIRTUAL-IP sowie optionale Befehle wie standby GROUP priority VALUE und standby GROUP preempt.

Parameter: GROUP = HSRP-Gruppennummer; VIRTUAL-IP = gemeinsames Gateway; VALUE = Priorität (typischer Wertebereich 0–255, Standard häufig 100).

interface Vlan10
 ip address 192.168.10.2 255.255.255.0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt

Prüfen: show standby brief. Beide Router müssen dieselbe Gruppe und virtuelle IP verwenden.

Wireless – Catalyst 9800

show ap summary

Zweck: Zeigt erkannte Access Points und ihren Join-Status am Controller.

Plattform: Catalyst 9800 Wireless Controller; nicht als allgemeiner Switch-Befehl verwenden.

Syntax: show ap summary

show ap summary
show ap name AP-NAME config general

Parameter: Der AP-Name wird bei Detailabfragen ergänzt; exakte Unterbefehle hängen vom IOS-XE-Release ab.

show wireless client summary

Zweck: Übersicht der verbundenen WLAN-Clients.

Plattform: Catalyst 9800; Syntax und Detailoptionen releaseabhängig.

Syntax: show wireless client summary

show wireless client summary

Praxis: Bei Client-Problemen anschließend mit MAC-Adresse gezielte Detail- und Policy-Informationen abrufen.

Qualitätsregel für diese Datenbank: Jeder neue Befehl erhält dieselben Felder: Zweck, Plattform/Version, Syntax, Erklärung jedes Parameters, Beispiel, Verifikation, typische Fehler und Sicherheits-/Änderungshinweise. Komplexe Befehle bekommen zusätzlich vollständige Praxislabs mit mehreren Geräten.
