Nexus NX-OS Command Reference

Eigene Befehlsreferenz für Cisco Nexus. NX-OS ist nicht identisch mit Catalyst IOS/IOS-XE: Syntax, Features und Betriebsmodell immer anhand des Nexus-Modells und Releases prüfen.

Wichtig: Nexus-Funktionen werden häufig mit feature aktiviert. Nicht jede Funktion ist auf jedem Nexus-Modell oder NX-OS-Release verfügbar. Vor Änderungen Hardware-/Software-Kompatibilität und Auswirkungen auf den Fabric prüfen.

System und Feature-Verwaltung

show version

Zweck: Zeigt Modell, NX-OS-Version, Systemlaufzeit und Hardwareinformationen.

Plattform: Cisco Nexus NX-OS.

Syntax: show version

show version

Praxis: Vor jeder Änderung genaue Plattform und NX-OS-Version dokumentieren.

show module

Zweck: Zeigt installierte Module und deren Status, soweit das Nexus-Modell modulare Hardware verwendet.

Plattform: Modellabhängig auf Nexus NX-OS.

Syntax: show module

show module

Hinweis: Bei Fixed-Form-Factor-Geräten können Informationen und Ausgabe abweichen.

show feature

Zweck: Zeigt unterstützte und aktivierte NX-OS-Features.

Plattform: Nexus NX-OS.

Syntax: show feature

show feature
show feature | include ospf

Praxis: Vor Routing-, vPC- oder anderen Feature-Konfigurationen prüfen, ob die benötigte Funktion verfügbar und aktiviert ist.

feature ospf

Zweck: Aktiviert das OSPF-Feature auf unterstützten Nexus-Plattformen.

Plattform: Nexus NX-OS; Lizenz-, Plattform- und Release-Anforderungen prüfen.

Syntax: feature ospf

configure terminal
feature ospf
show feature | include ospf

Achtung: Das Aktivieren eines Features allein konfiguriert noch keine OSPF-Nachbarschaften oder Routen.

Switching und VLAN

vlan

Zweck: Erstellt ein VLAN und öffnet dessen Konfigurationsmodus.

Plattform: Nexus NX-OS.

Syntax: vlan VLAN-ID; anschließend optional name VLAN-NAME.

configure terminal
vlan 20
 name SERVERS
show vlan brief

Prüfen: VLAN-Status und VLAN-Zuordnung der Interfaces kontrollieren.

switchport mode

Zweck: Definiert einen Layer-2-Port als Access oder Trunk.

Plattform: Nexus NX-OS Ethernet-Interfaces mit Layer-2-Modus.

Syntax: switchport mode { access | trunk }

interface Ethernet1/10
 switchport
 switchport mode access
 switchport access vlan 20
 no shutdown

Hinweis: Auf Nexus kann ein Interface zunächst Layer 3 sein. switchport setzt es – sofern unterstützt – in den Layer-2-Modus.

switchport trunk allowed vlan

Zweck: Begrenzt die VLANs, die über einen Trunk transportiert werden.

Plattform: Nexus NX-OS Layer-2-Trunk-Interfaces.

Syntax: switchport trunk allowed vlan { VLAN-LIST | add VLAN-LIST | remove VLAN-LIST | all | none }; genaue Optionen releaseabhängig.

interface Ethernet1/1
 switchport
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
show interface trunk

Achtung: VLAN-Listen auf beiden Seiten des Links vergleichen. Eine falsche Liste kann VLANs vom Fabric trennen.

show interface status

Zweck: Zeigt Portstatus und grundlegende Interface-Informationen.

Plattform: Nexus NX-OS.

Syntax: show interface status

show interface status
show interface Ethernet1/1

Hinweis: NX-OS verwendet in vielen Befehlen die Schreibweise show interface im Singular.

Port-Channel und vPC

feature lacp

Zweck: Aktiviert LACP-Unterstützung auf Nexus-Plattformen, auf denen das Feature separat eingeschaltet werden muss.

Plattform: Nexus NX-OS; Feature-Anforderungen modell-/releaseabhängig.

Syntax: feature lacp

configure terminal
feature lacp
show feature | include lacp

channel-group

Zweck: Fügt ein Ethernet-Interface einem Port-Channel hinzu.

Plattform: Nexus NX-OS; LACP oder statische Bündelung nach Design.

Syntax: channel-group GROUP-ID mode { active | passive | on }

Parameter: GROUP-ID = Port-Channel-Nummer; active/passive = LACP; on = statische Bündelung ohne LACP-Aushandlung.

feature lacp
interface Ethernet1/1
 channel-group 10 mode active
interface Ethernet1/2
 channel-group 10 mode active
interface port-channel10
 switchport
 switchport mode trunk
 no shutdown
show port-channel summary

Prüfen: Beide Seiten müssen konsistente Einstellungen haben; Member-Ports müssen als gebündelt angezeigt werden.

show port-channel summary

Zweck: Zeigt Port-Channel-Gruppen, Protokoll und Member-Status.

Plattform: Nexus NX-OS.

Syntax: show port-channel summary

show port-channel summary
show interface port-channel 10

Auswertung: Prüfe, ob die erwarteten Member-Interfaces aktiv und gebündelt sind; Statuskennzeichen in der Ausgabe anhand der jeweiligen NX-OS-Version interpretieren.

show vpc

Zweck: Zeigt vPC-Domäne und Peer-/Consistency-Status.

Plattform: Nexus-Modelle mit vPC-Unterstützung.

Syntax: show vpc; ergänzend show vpc brief und show vpc consistency-parameters global, sofern unterstützt.

show vpc
show vpc brief
show vpc consistency-parameters global

Hinweis: vPC benötigt ein sorgfältig geplantes Peer-Link- und Keepalive-Design. Die beiden Peer-Switches müssen kompatible Konfigurationen und unterstützte Plattformen verwenden.

Layer 3 und Routing

no switchport

Zweck: Setzt ein Nexus-Interface in den Layer-3-Routed-Modus, sofern das Modell dies unterstützt.

Plattform: Nexus NX-OS.

Syntax: no switchport

interface Ethernet1/10
 no switchport
 ip address 192.0.2.1/30
 no shutdown
show ip interface brief

Hinweis: IP-Präfixschreibweise und Interface-Fähigkeit anhand der Plattform prüfen.

ip route

Zweck: Erstellt eine statische IPv4-Route.

Plattform: Nexus NX-OS; VRF- und Next-Hop-Syntax je nach Version.

Syntax: ip route PREFIX/PREFIX-LENGTH NEXT-HOP

ip route 192.0.2.0/24 198.51.100.1
show ip route
show ip route 192.0.2.0/24

Hinweis: Dokumentationsadressen verwenden; Next-Hop-Erreichbarkeit und VRF-Kontext prüfen.

router ospf

Zweck: Konfiguriert einen OSPF-Prozess auf Nexus NX-OS.

Plattform: Nexus mit OSPF-Feature und passender Unterstützung.

Syntax: router ospf PROCESS; Interface-Aktivierung erfolgt typischerweise im Interface-Kontext mit ip router ospf PROCESS area AREA.

feature ospf
router ospf UNDERLAY
 router-id 1.1.1.1
interface Ethernet1/49
 no switchport
 ip address 192.0.2.1/30
 ip router ospf UNDERLAY area 0.0.0.0
 no shutdown
show ip ospf neighbors
show ip route ospf

Wichtig: NX-OS OSPF-Konfiguration unterscheidet sich von IOS/IOS-XE. Area- und Interface-Befehle nicht ungeprüft übertragen.

Speichern und Fehlerdiagnose

copy running-config startup-config

Zweck: Speichert die laufende Konfiguration dauerhaft.

Plattform: Nexus NX-OS.

Syntax: copy running-config startup-config

copy running-config startup-config

Hinweis: Vorher Konfiguration und Auswirkungen kontrollieren.

show logging logfile

Zweck: Zeigt Einträge aus dem NX-OS-System-Logfile.

Plattform: Nexus NX-OS; verfügbare Filteroptionen releaseabhängig.

Syntax: show logging logfile

show logging logfile
show logging logfile | include Ethernet1/1

Praxis: Mit Interface-Countern und Zeitstempeln korrelieren.

show interface counters errors

Zweck: Prüft Fehlerzähler der Interfaces.

Plattform: Nexus NX-OS; verfügbare Counter je Plattform.

Syntax: show interface counters errors

show interface counters errors
show interface Ethernet1/1

Praxis: CRC, Drops, Discards und Link-Flaps mit Transceiver- und Kabeldiagnose abgleichen.
