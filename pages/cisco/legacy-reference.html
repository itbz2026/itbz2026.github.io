VLAN

VLAN erstellen und Access-Port zuweisen

Ein VLAN trennt ein Layer-2-Netz logisch in eigene Broadcast-Domänen.

show vlan brief
configure terminal
vlan 10
 name MANAGEMENT
exit
interface gigabitEthernet 0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
end
show vlan brief

Weitere Befehle: show vlan id 10, no vlan 10, show interfaces switchport.

Trunking

Mehrere VLANs über eine Verbindung transportieren

configure terminal
interface gigabitEthernet 0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30,99
 switchport trunk native vlan 99
 no shutdown
end
show interfaces trunk
show interfaces gi0/24 switchport
Native VLAN und erlaubte VLANs müssen an beiden Enden zusammenpassen. Prüfe die Plattformunterstützung; manche Modelle benötigen zusätzliche oder abweichende Befehle.

STP

Spanning Tree Protocol

STP verhindert Layer-2-Schleifen. Rapid-PVST ist eine Cisco-Implementierung mit separaten STP-Instanzen pro VLAN.

show spanning-tree
show spanning-tree summary
show spanning-tree vlan 10
show spanning-tree root
show spanning-tree detail

configure terminal
spanning-tree mode rapid-pvst
spanning-tree vlan 10 root primary
interface gigabitEthernet 0/1
 spanning-tree portfast
 spanning-tree bpduguard enable
end
show spanning-tree
PortFast und BPDU Guard nur auf geeigneten Endgeräte-Ports verwenden, nicht auf Switch-Uplinks. Vor Änderungen Root-Bridge und Topologie prüfen.

Mehrere Links bündeln

VTP · VLAN Trunking Protocol

VTP verstehen: Version 1, 2 und 3

VTP verteilt VLAN-Informationen innerhalb derselben VTP-Domain über Trunk-Verbindungen. Alle Switches müssen denselben Domain-Namen und ein kompatibles VTP-Design verwenden. VTP ersetzt keine Trunk-Konfiguration. VTP-Versionen und Interoperabilität unterscheiden sich nach Plattform und Softwarestand.

VersionWichtige EigenschaftenHinweis
VTP v1Grundlegende VLAN-Verteilung; klassische VTP-FunktionLegacy; nur einsetzen, wenn erforderlich
VTP v2Verbesserte Behandlung unbekannter TLVs; zusätzliche KonsistenzfunktionenV1/V2-Mischbetrieb nur gemäß Cisco-Kompatibilitätsregeln; v2 muss auf allen teilnehmenden Geräten unterstützt und passend aktiviert sein
VTP v3Unterstützt Extended VLANs und Private VLANs; Primary-Server-Konzept; verbesserte KontrolleFür moderne unterstützte Umgebungen bevorzugt; Kompatibilität prüfen

Wichtige VTP-Modi

  • Server: Kann VLAN-Datenbank ändern und verteilen. Bei VTP v3 muss ein Primary Server Änderungen an der VLAN-Datenbank vornehmen.
  • Client: Übernimmt VLAN-Informationen und kann sie nicht lokal verwalten.
  • Transparent: Verwaltet VLANs lokal; leitet VTP-Nachrichten je nach Version/Plattform weiter, nimmt aber nicht an der VLAN-Verteilung teil.
  • Off: VTP-Nachrichten werden nicht weitergeleitet; Verfügbarkeit abhängig von Plattform und Version.

VTP-Status prüfen

show vtp status
show vtp counters
show vlan brief
show interfaces trunk
show running-config | include vtp

Beispiel: VTP v2 – Server und Client

Nur in einer isolierten Testumgebung verwenden. Beispiel-Domain: LABNET.

! Auf dem Server-Switch
configure terminal
vtp domain LABNET
vtp version 2
vtp mode server
vtp password MeinVtpPasswort
end
show vtp status

! Auf dem Client-Switch
configure terminal
vtp domain LABNET
vtp version 2
vtp mode client
vtp password MeinVtpPasswort
end
show vtp status

! Auf beiden Switches: Uplink als Trunk konfigurieren
configure terminal
interface gigabitEthernet 0/24
 switchport mode trunk
 no shutdown
end

Beispiel: VTP v3 – Primary Server

! Auf jedem Switch der Domain
configure terminal
vtp domain LABNET
vtp version 3
vtp password MeinVtpPasswort
end

! Auf dem vorgesehenen Primary Server
vtp primary vlan
show vtp status

! VLAN zentral erstellen
configure terminal
vlan 10
 name CLIENTS
vlan 20
 name SERVERS
end
show vlan brief
show vtp status

VTP sicher prüfen – bevor du einen Switch verbindest

  • show vtp status: Version, Domain, Modus und Configuration Revision kontrollieren.
  • Ein Switch mit höherer Configuration Revision kann in bestimmten VTP-Szenarien unerwartet VLAN-Informationen verteilen.
  • Vor dem Anschluss eines gebrauchten Switches VTP-Modus, Domain und Revision prüfen; bei Unsicherheit zuerst isolieren und sauber vorbereiten.
  • VTP-Passwort und identische Domain auf allen teilnehmenden Geräten konfigurieren.
  • VTP v3 Primary-Server-Rolle bewusst vergeben.
  • Viele Netzwerke nutzen bewusst vtp mode transparent oder vtp mode off, um unerwünschte zentrale VLAN-Verteilung zu vermeiden.
Achtung: VTP kann bei falscher Domain-/Revision-Konstellation VLAN-Konfigurationen verändern. Niemals ungeprüft einen gebrauchten Switch in ein produktives VTP-Netz stecken. Befehle und unterstützte Modi hängen vom Switch-Modell und IOS/IOS XE ab.

HSRP · Gateway Redundancy

HSRP – redundantes Default Gateway

HSRP stellt Hosts eine virtuelle Gateway-IP bereit. Ein Router/Switch ist Active, der andere Standby. Beispiel: VLAN 10, virtuelle IP 192.168.10.1.

Switch A – bevorzugt Active

configure terminal
interface vlan 10
 ip address 192.168.10.2 255.255.255.0
 standby version 2
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 no shutdown
end
show standby brief
show standby vlan 10

Switch B – Standby

configure terminal
interface vlan 10
 ip address 192.168.10.3 255.255.255.0
 standby version 2
 standby 10 ip 192.168.10.1
 standby 10 priority 100
 standby 10 preempt
 no shutdown
end
show standby brief

Hosts verwenden 192.168.10.1 als Default Gateway. HSRP Version und Befehle müssen auf beiden Geräten kompatibel sein.

VRRP · Gateway Redundancy

VRRP – offener Standard für Gateway-Redundanz

VRRP wählt einen Master und Backup-Router. Beispiel für VLAN 20: virtuelle IP 192.168.20.1.

! Router/Switch A
configure terminal
interface vlan 20
 ip address 192.168.20.2 255.255.255.0
 vrrp 20 ip 192.168.20.1
 vrrp 20 priority 120
 vrrp 20 preempt
 no shutdown
end
show vrrp brief
show vrrp
! Router/Switch B
configure terminal
interface vlan 20
 ip address 192.168.20.3 255.255.255.0
 vrrp 20 ip 192.168.20.1
 vrrp 20 priority 100
 vrrp 20 preempt
 no shutdown
end
show vrrp brief
VRRP-Unterstützung und Syntax hängen von Plattform und IOS/IOS XE ab. Nicht jede Catalyst-Plattform unterstützt alle VRRP-Optionen.
OSPF · Dynamic Routing

OSPF – dynamisches Routing konfigurieren

OSPF ist ein Link-State-Routing-Protokoll. Router tauschen Informationen aus und berechnen den besten Pfad. Beispiel: Area 0, Router-ID 1.1.1.1.

configure terminal
router ospf 10
 router-id 1.1.1.1
 network 192.168.10.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0
 passive-interface default
 no passive-interface gigabitEthernet 1/0/24
end
show ip ospf neighbor
show ip ospf interface brief
show ip route ospf
show ip protocols

Wildcard 0.0.0.255 entspricht dem Netz 192.168.10.0/24. OSPF-Nachbarn benötigen passende Area-, Timer-, Authentifizierungs- und Netzwerkeinstellungen.

EIGRP · Dynamic Routing

EIGRP – Cisco Routing-Protokoll

Beispiel mit Autonomous System 100. Die klassische EIGRP-Syntax wird nicht auf jeder Plattform oder jedem IOS-XE-Release unterstützt.

configure terminal
router eigrp 100
 network 192.168.10.0 0.0.0.255
 network 10.0.0.0 0.0.0.3
 no auto-summary

 no passive-interface gigabitEthernet 1/0/24
end
show ip eigrp neighbors
show ip eigrp topology
show ip protocols

EIGRP ist nicht auf allen Catalyst-Switches verfügbar. Prüfe Lizenz, Plattform und Softwareversion. Bei Named Mode unterscheidet sich die Konfiguration.
QoS · Quality of Service

QoS – Datenverkehr priorisieren

QoS klassifiziert und behandelt Datenverkehr nach Regeln. Beispiel: Sprachverkehr mit DSCP EF (46) erkennen und priorisieren. Das Beispiel nutzt MQC und muss an Bandbreite und Plattform angepasst werden.

configure terminal
class-map match-any VOICE
 match dscp ef
exit
policy-map WAN-OUT
 class VOICE
  priority percent 20
 class class-default
  fair-queue
exit
interface gigabitEthernet 1/0/48
 service-policy output WAN-OUT
end
show policy-map
show policy-map interface gigabitEthernet 1/0/48
show class-map
show running-config | section policy-map
QoS-Funktionen und Syntax unterscheiden sich stark zwischen Catalyst-Serien. Eine Priority Queue kann bei Überlastung strikt priorisiert werden. Prozentwerte und Policy müssen zur tatsächlichen Link-Bandbreite passen.
DHCP Snooping · Layer 2 Security

DHCP Snooping aktivieren

DHCP Snooping schützt vor unerlaubten DHCP-Servern. Client-Ports bleiben standardmäßig untrusted; nur der Port in Richtung legitimer DHCP-Server bzw. DHCP-Uplink wird trusted gesetzt.

configure terminal
ip dhcp snooping
ip dhcp snooping vlan 10,20
no ip dhcp snooping information option
interface gigabitEthernet 1/0/48
 description Uplink-to-DHCP-Server
 ip dhcp snooping trust
exit
interface range gigabitEthernet 1/0/1-24
 ip dhcp snooping limit rate 15
end
show ip dhcp snooping
show ip dhcp snooping binding
show ip dhcp snooping statistics
Nur echte DHCP-Server-/Relay-Uplinks als trusted markieren. Ein falscher Trust-Port kann den Schutz aushebeln. Option 82 nur deaktivieren, wenn das Design es erfordert.
DAI · Dynamic ARP Inspection

Dynamic ARP Inspection konfigurieren

DAI prüft ARP-Pakete gegen DHCP-Snooping-Bindings und hilft, ARP-Spoofing zu verhindern. DHCP Snooping muss für dynamische Clients passend eingerichtet sein.

configure terminal
ip arp inspection vlan 10,20
interface gigabitEthernet 1/0/48
 description Trusted-Uplink
 ip arp inspection trust
exit
interface range gigabitEthernet 1/0/1-24
 ip arp inspection limit rate 15
end
show ip arp inspection
show ip arp inspection interfaces
show ip arp inspection statistics
show ip dhcp snooping binding
DAI kann legitime ARP-Pakete blockieren, wenn Binding-Daten fehlen oder Hosts statische IP-Adressen nutzen. Vor dem Aktivieren statische ARP-ACLs und Trust-Grenzen planen. Trust nur auf vertrauenswürdigen Uplinks setzen.
IP Source Guard

IP Source Guard – IP/MAC-Spoofing begrenzen

IP Source Guard filtert IP-Verkehr an einem Access-Port anhand der DHCP-Snooping-Binding-Tabelle.

configure terminal
ip dhcp snooping
ip dhcp snooping vlan 10
interface gigabitEthernet 1/0/10
 switchport mode access
 switchport access vlan 10
 ip verify source
end
show ip verify source
show ip dhcp snooping binding
show interfaces status

Bei statischen Hosts kann je nach Plattform eine statische IP Source Binding-Konfiguration nötig sein. Erst in einem Test-VLAN prüfen.

SPAN · Port Mirroring

SPAN – Traffic für Wireshark spiegeln

SPAN kopiert Verkehr eines Quellports oder VLANs auf einen Analyse-Port. Beispiel: Quellport Gi1/0/10, Zielport Gi1/0/20.

configure terminal
monitor session 1 source interface gigabitEthernet 1/0/10 both
monitor session 1 destination interface gigabitEthernet 1/0/20
end
show monitor session 1
show monitor session all

Am Zielport einen PC mit Wireshark anschließen. Der Zielport wird für die Spiegelung verwendet und ist in der Regel nicht gleichzeitig ein normaler Client-Port.

Storm Control

Broadcast-, Multicast- und Unknown-Unicast-Stürme begrenzen

configure terminal
interface gigabitEthernet 1/0/10
 storm-control broadcast level 5.00
 storm-control multicast level 5.00
 storm-control action trap
end
show storm-control
show storm-control interface gigabitEthernet 1/0/10

Die Schwellenwerte sind Beispiele, keine allgemeingültigen Empfehlungen. Vor dem Einsatz normalen Broadcast-/Multicast-Verkehr messen und Plattformsyntax prüfen.
