Automatisierung & API

pvesh, REST API, Tokens, Terraform, Ansible und Cloud-Init

Geltungsbereich: Jeweils Proxmox VE oder PBS/Datacenter Manager wie im Artikel angegeben. Befehle auf dem Proxmox-Host ausführen, sofern nicht anders angegeben. Syntax und Funktionen können versionsabhängig sein; lokale Hilfe und offizielle Dokumentation prüfen.
Praxisreferenz

pvesh entdecken

`pvesh` stellt die Proxmox API-Funktionen lokal über CLI bereit. Pfade und Parameter mit Hilfe beziehungsweise API Viewer erkunden.

pvesh help
pvesh get /nodes
pvesh get /cluster/resources
Verfügbare Endpunkte und Parameter hängen von Version und Berechtigungen ab.
Praxisreferenz

REST API und Authentifizierung

Die REST API nutzt HTTPS und Proxmox-Authentifizierung. Für Automatisierung API-Tokens mit minimalen ACLs verwenden.

curl -k https://<PVE_HOST>:8006/api2/json/version
`-k` deaktiviert Zertifikatsprüfung und ist nur für isolierte Tests geeignet. Produktiv Zertifikate korrekt validieren; Secrets nicht in Shell-History speichern.
Praxisreferenz

API-Token-Prinzip

Token-ID und Secret werden für nichtinteraktive Zugriffe verwendet. Privilege Separation begrenzt Rechte zusätzlich zur Benutzer-ACL.

pveum user token list <USER>@<REALM>
Token-Secret sicher in Secret Manager speichern, rotieren und bei Bedarf widerrufen.
Praxisreferenz

Terraform und Ansible

Terraform Provider und Ansible-Module können VM-Provisionierung und Konfiguration automatisieren. Versionen, Provider-Dokumentation und API-Berechtigungen pinnen.

terraform version
ansible --version
Vor produktivem Einsatz State-Dateien und Secrets schützen. Änderungen zuerst in Lab-Umgebung testen.
Praxisreferenz

Cloud-Init und Provisionierung

Cloud-Init automatisiert Erstkonfiguration von unterstützten Linux-Gästen. Template, Cloud-Init-Laufwerk, User, SSH-Key und Netzwerkparameter vorbereiten.

qm cloudinit dump <VMID> user
qm cloudinit dump <VMID> network
Cloud-Init-Optionen hängen von VM-Konfiguration und Gast-Image ab. Zugangsdaten nicht unverschlüsselt in Vorlagen speichern.

Erweiterte Administration & Praxis

Zusätzliche Aufgaben für Betrieb, Diagnose und Expertenpraxis.

Erweiterte Praxisreferenz

API-Endpunkte erkunden

API Viewer und pvesh zeigen verfügbare Pfade und Parameter der installierten Version.

pvesh ls /
pvesh ls /nodes
pvesh get /version
Hinweis: Nicht alle Endpunkte sind für jeden Benutzer verfügbar. API-Token-Rechte vor Automatisierung testen.
Erweiterte Praxisreferenz

Automatisierung idempotent gestalten

Skripte sollen zuerst den Ist-Zustand prüfen und nur notwendige Änderungen ausführen.

pvesh get /cluster/resources --output-format json
Hinweis: Wiederholbare Aufrufe, Logging, Exit-Codes und Task-Abschlusskontrolle implementieren.
Betriebssicherheit: Destruktive Änderungen an Storage, Netzwerk, Cluster oder Gastkonfiguration nur mit geprüftem Backup, Wartungsplan und Rückweg durchführen.
