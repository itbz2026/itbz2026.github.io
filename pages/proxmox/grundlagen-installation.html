Grundlagen & Installation

Installation, Erstkonfiguration, Repositories und Host-Basics

Geltungsbereich: Proxmox VE. Befehle auf dem Proxmox-Host ausführen, sofern nicht anders angegeben. Syntax und Funktionen können sich zwischen Versionen unterscheiden. Lokale Hilfe und Dokumentation der installierten Version prüfen.
Praxisreferenz

Installation vorbereiten

Proxmox VE wird direkt auf Hardware installiert. Vorher CPU-Virtualisierung (Intel VT-x/AMD-V), RAM, Datenträger, Netzwerkports und Hardware-Kompatibilität prüfen.

BIOS/UEFI, Bootmodus, Ziel-Datenträger und Management-Netz planen. Die Installation kann den Ziel-Datenträger vollständig überschreiben.
Praxisreferenz

Erstdiagnose nach Installation

Proxmox-Version, Hostname, Interfaces, Routing, DNS, Zeit und fehlgeschlagene Dienste kontrollieren.

pveversion -v
hostnamectl
ip -br address
ip route
cat /etc/resolv.conf
timedatectl status
systemctl --failed
Befehle auf dem Proxmox-Host ausführen.
Praxisreferenz

APT-Repositories und Updates

Paketindizes aktualisieren, verfügbare Updates anzeigen und geplante Updates einspielen.

apt update
apt list --upgradable
apt full-upgrade
Enterprise- und No-Subscription-Repositories passend zur Subscription und installierten Version konfigurieren. Vor größeren Updates Release Notes, Backup und Wartungsfenster prüfen.
Praxisreferenz

Hostname und Namensauflösung

Der Node benötigt einen stabilen FQDN und konsistente DNS- beziehungsweise Hosts-Auflösung.

hostnamectl
getent hosts $(hostname -f)
getent hosts pve01.example.com
cat /etc/hosts
Im Cluster Hostname oder Management-IP niemals unkoordiniert ändern.
Praxisreferenz

Wichtige Pfade und Dienste

/etc/pve wird durch pmxcfs bereitgestellt. Wichtige Dienste stellen Webproxy, API, Statusdaten und Cluster-Konfiguration bereit.

ls -la /etc/pve/
systemctl status pveproxy pvedaemon pvestatd pve-cluster
journalctl -u pveproxy -b --no-pager
Dateien unter /etc/pve nicht wie gewöhnliche lokale Dateien behandeln. Änderungen können clusterweit wirken.
Betriebssicherheit: Destruktive Änderungen an Storage, Netzwerk, Cluster oder Gastkonfiguration nur mit geprüftem Backup, Wartungsplan und Rückweg durchführen. Platzhalter wie <VMID> und <CTID> durch echte Werte ersetzen.
