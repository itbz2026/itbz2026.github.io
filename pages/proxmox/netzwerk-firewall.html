Netzwerk & Firewall

Linux Bridges, VLANs, Bonds, Routing und Proxmox Firewall

Geltungsbereich: Jeweils Proxmox VE oder PBS/Datacenter Manager wie im Artikel angegeben. Befehle auf dem Proxmox-Host ausführen, sofern nicht anders angegeben. Syntax und Funktionen können versionsabhängig sein; lokale Hilfe und offizielle Dokumentation prüfen.
Praxisreferenz

Interfaces und Bridges prüfen

ip -br link ip -br address ip route bridge link bridge vlan show

Zeigt Interfaces, IPs, Routing, Bridge-Mitglieder und VLAN-Zuordnungen.
Vor Netzwerkänderungen lokalen Konsolenzugriff sicherstellen. Fehler können den Webzugriff auf den Host trennen.
Praxisreferenz

Linux Bridge und VLAN-aware

Eine Linux Bridge verbindet virtuelle NICs mit physischen Interfaces. VLAN-aware Bridges transportieren mehrere VLANs; VLAN-Tags werden an VM-NICs oder über Trunks zugewiesen.

cat /etc/network/interfaces
bridge vlan show
Änderungen an `/etc/network/interfaces` nur mit passendem Netzwerkplan und Rückfallzugang anwenden. VLAN-Tagging muss auch auf Switchports korrekt sein.

Bonding und LACP

Bonds bündeln physische Interfaces. LACP (802.3ad) benötigt passende Switch-Konfiguration und kompatible Link-Parameter.

cat /proc/net/bonding/bond0
ip -d link show bond0
ethtool <NIC>
Beispielinterface `bond0` und `` anpassen. Bond-Modus und Switch-Konfiguration müssen zusammenpassen.

Firewall-Ebenen

Proxmox Firewall kann auf Datacenter-, Node- und Gast-Ebene Regeln anwenden. Regeln, IP Sets und Security Groups zentral dokumentieren.

pve-firewall status
systemctl status pve-firewall
journalctl -u pve-firewall -b --no-pager
Vor Aktivierung Regeln für Managementzugriff, Clusterverkehr, Storage und benötigte Gastdienste planen. Lockout-Risiko beachten.
Praxisreferenz

Netzwerkdiagnose

Für Paketverlust, MTU, DNS und Port-Erreichbarkeit systematisch Layer für Layer prüfen.

ping -c 4 <GATEWAY>
tracepath <ZIEL>
ss -tulpn
ethtool <NIC>
tcpdump -ni <IFACE>
Platzhalter ersetzen. Paketmitschnitte können sensible Inhalte enthalten; sicher speichern und nach Analyse löschen.

MTU und Jumbo Frames prüfen

MTU muss über physische Links, Bridges, Bonds, Switches und Overlay-Netze konsistent sein.

ip link show
ip -d link show <IFACE>
ping -M do -s 1472 <ZIEL>
Hinweis: Die passende Ping-Nutzlast hängt von IP-Version und gewünschter MTU ab. Jumbo Frames Ende-zu-Ende testen.
Erweiterte Praxisreferenz

Firewall-Regeln vor Aktivierung prüfen

Management-, Cluster-, Storage- und Migrationsverkehr müssen in den Regeln berücksichtigt werden.

pve-firewall status
systemctl status pve-firewall
journalctl -u pve-firewall -b --no-pager
Hinweis: Regeländerungen zuerst mit Konsolenzugriff und Rückfallplan testen.
Betriebssicherheit: Destruktive Änderungen an Storage, Netzwerk, Cluster oder Gastkonfiguration nur mit geprüftem Backup, Wartungsplan und Rückweg durchführen.
