Proxmox Internals & Systemverwaltung

pmxcfs, Dienste, Konfiguration, Tasks und Logs

Geltungsbereich: Jeweils Proxmox VE oder PBS/Datacenter Manager wie im Artikel angegeben. Befehle auf dem Proxmox-Host ausführen, sofern nicht anders angegeben. Syntax und Funktionen können versionsabhängig sein; lokale Hilfe und offizielle Dokumentation prüfen.
Praxisreferenz

pmxcfs und /etc/pve

`/etc/pve` ist das clusterweite Proxmox Configuration File System. Es wird durch `pve-cluster`/pmxcfs bereitgestellt.

mount | grep /etc/pve
systemctl status pve-cluster
ls -la /etc/pve
Keine direkten Eingriffe in interne Datenbank- oder Laufzeitdateien ohne dokumentiertes Recovery-Verfahren.
Praxisreferenz

Zentrale Dienste

pveproxy stellt Web/API bereit, pvedaemon verarbeitet Verwaltungsaufgaben, pvestatd sammelt Statusdaten und pve-cluster stellt pmxcfs bereit.

systemctl status pveproxy pvedaemon pvestatd pve-cluster
systemctl --failed
Dienste nicht pauschal neu starten, wenn laufende Aufgaben oder Clusteroperationen betroffen sind.
Praxisreferenz

Tasks und Logs

Proxmox-Aufgaben lassen sich über Webinterface und CLI nachvollziehen. Systemlogs ergänzen die Task-Ausgabe.

pvenode task list
journalctl -b --no-pager
journalctl -u pvedaemon -b --no-pager
Zeitstempel und Task-ID notieren, bevor Logs rotiert oder bereinigt werden.
Praxisreferenz

Konfiguration und Backup

VM-Konfigurationen und Cluster-Konfigurationen sind Teil der Betriebsdokumentation. Vor Änderungen Konfiguration und zugehörige Storage-/Netzwerkdaten erfassen.

qm config <VMID>
pct config <CTID>
cp /etc/network/interfaces /root/interfaces.backup
Kopien von `/etc/pve` nicht als eigenständige, konsistente Cluster-Sicherung betrachten. Offizielle Backup-/Recovery-Verfahren nutzen.
Praxisreferenz

Zertifikate und Proxy

Webproxy-Zertifikate, ACME und Zertifikatserneuerung kontrolliert verwalten.

pvenode cert info
systemctl status pveproxy
journalctl -u pveproxy -b --no-pager
Private Schlüssel schützen und Zertifikatswechsel mit Zugriffstest und Rollback planen.

CLI und API unterscheiden

pvesh stellt API-Funktionen lokal bereit; qm, pct und pvesm sind spezialisierte Werkzeuge. Nicht jede API-Operation hat eine identische CLI-Option.

pvesh help
qm help
pct help
pvesm help
Hinweis: Hilfe der installierten Version verwenden statt Syntax aus älteren Tutorials ungeprüft zu übernehmen.
Erweiterte Praxisreferenz

Diagnosebericht sammeln

Versionsstand, Hardware, Dienste und Fehlerlogs für eine reproduzierbare Diagnose erfassen.

pveversion -v
pvereport
systemctl --failed
Hinweis: Berichte können Hostnamen, IP-Adressen und sensible Informationen enthalten. Vor Weitergabe prüfen.
Betriebssicherheit: Destruktive Änderungen an Storage, Netzwerk, Cluster oder Gastkonfiguration nur mit geprüftem Backup, Wartungsplan und Rückweg durchführen.
