Virtuelle Maschinen (QEMU/KVM)

VM-Lifecycle, Hardware, Templates, Migration und qm-Befehle

Geltungsbereich: Proxmox VE. Befehle auf dem Proxmox-Host ausführen, sofern nicht anders angegeben. Syntax und Funktionen können sich zwischen Versionen unterscheiden. Lokale Hilfe und Dokumentation der installierten Version prüfen.
Praxisreferenz

VMs auflisten und prüfen

qm list zeigt VMs; qm status zeigt den Laufzustand; qm config liest die Konfiguration.

qm list
qm status <VMID>
qm config <VMID>
qm showcmd <VMID> --pretty
<VMID> durch die numerische VM-ID ersetzen. showcmd ist eine Diagnoseausgabe.
Praxisreferenz

VM erstellen – Beispiel

Beispiel für eine VM mit 4 GiB RAM, 2 vCPU, VirtIO-Netzwerk und 32-GiB-Systemdisk.

qm create 120 --name debian-lab --memory 4096 --cores 2 --net0 virtio,bridge=vmbr0
qm set 120 --scsihw virtio-scsi-single
qm set 120 --scsi0 local-lvm:32
qm set 120 --boot order=scsi0
qm config 120
VM-ID, Bridge und Storage müssen frei beziehungsweise vorhanden sein. Vorher pvesm status und ip -br link prüfen.
Praxisreferenz

CPU und RAM

CPU-Typ, Kerne, NUMA, RAM und Ballooning anhand des Workloads festlegen. Host-Ressourcen reservieren.

qm config <VMID>
qm set <VMID> --cores 4 --memory 8192
qm set <VMID> --balloon 2048
Ballooning benötigt Gastunterstützung und ist nicht für jeden Workload sinnvoll.
Praxisreferenz

Snapshots und Klone

Snapshots eignen sich für kurzfristige Tests. Klone erstellen neue VMs auf Basis einer vorhandenen VM oder Vorlage.

qm listsnapshot <VMID>
qm snapshot <VMID> vor-update --description "Vor Wartung"
qm clone <VMID> <NEWID> --name test-clone
Storage-Unterstützung und VM-Zustand prüfen. Snapshots ersetzen keine unabhängigen Backups.
Praxisreferenz

Migration und Guest Agent

Online-Migration erfordert kompatible CPU-/Maschineneinstellungen, passende Storage-Verfügbarkeit und ausreichende Netzwerkkapazität.

qm migrate <VMID> <TARGET_NODE> --online
qm agent <VMID> ping
qm agent <VMID> get-osinfo
Guest Agent muss im Gast installiert und aktiviert sein. Optionen mit qm help migrate auf der installierten Version prüfen.
Praxisreferenz

VM-Lifecycle: Start, Shutdown und Reboot

Gäste möglichst sauber über das Betriebssystem oder den ACPI-Shutdown beenden. qm stop entspricht einem harten Ausschalten.

qm start <VMID>
qm status <VMID>
qm shutdown <VMID> --timeout 60
qm reboot <VMID>
qm stop <VMID>
Achtung: qm stop nur verwenden, wenn ein sauberer Shutdown nicht möglich oder ausdrücklich erforderlich ist. Ein harter Stopp kann Dateisysteme und Anwendungen im Gast beeinträchtigen. Timeout-Optionen mit qm help shutdown der installierten Version prüfen.
Praxisreferenz

Autostart und Startreihenfolge

Abhängigkeiten wie Firewall, DNS oder Datenbankdienste bei automatischem VM-Start berücksichtigen.

qm set <VMID> --onboot 1
qm set <VMID> --startup order=2,up=30,down=60
qm config <VMID>
Startreihenfolge und Verzögerungen anhand der installierten Version und der tatsächlichen Dienstabhängigkeiten planen. Autostart ersetzt keine HA-Konfiguration.
Erweiterte Praxisreferenz

Template und vollständigen Klon erstellen

Eine vorbereitete VM nach Bereinigung und Generalisierung als Template markieren und daraus eine unabhängige VM erstellen.

qm shutdown <VMID>
qm template <VMID>
qm clone <TEMPLATE_VMID> <NEW_VMID> --name app01 --full 1
qm config <NEW_VMID>
Template-VM vor dem Umwandeln herunterfahren. Gastbetriebssystem vorbereiten (z. B. Cloud-Init oder Sysprep), eindeutige Hostnamen und Identitäten sicherstellen. Storage-Unterstützung und Klonmodus vorher prüfen.

Erweiterte Praxisreferenz

VM-Konfiguration analysieren

Die Konfiguration enthält CPU, RAM, BIOS/UEFI, Machine Type, Controller, Disks, NICs und Bootreihenfolge.

qm config <VMID>
qm showcmd <VMID> --pretty
qm help set
Hinweis: Änderungen an BIOS, Machine Type oder Controller können das Gastbetriebssystem beeinflussen. Vorher Backup erstellen.
Erweiterte Praxisreferenz

Virtuelle Disk verschieben

Vor einer Storage-Migration freien Platz, Backend-Funktionen und VM-Zustand prüfen.

pvesm status
qm config <VMID>
qm help move_disk
Hinweis: Die genaue Syntax mit `qm help move_disk` der installierten Version prüfen. Migration kann IO und Netzwerk stark belasten.
Betriebssicherheit: Destruktive Änderungen an Storage, Netzwerk, Cluster oder Gastkonfiguration nur mit geprüftem Backup, Wartungsplan und Rückweg durchführen. Platzhalter wie <VMID> und <CTID> durch echte Werte ersetzen.
