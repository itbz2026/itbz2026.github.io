Networking

Netzwerkgrundlagen, Protokolle und Diagnose

TCP/IP

Grundlagen

  • IP-Adresse: logische Adresse eines Interfaces.
  • Subnetzmaske / Präfix: definiert Netz- und Hostanteil.
  • Default Gateway: nächster Router für Ziele außerhalb des lokalen Netzes.
  • DNS: übersetzt Namen in Adressen.
  • DHCP: verteilt IP-Adresse, Gateway, DNS und weitere Optionen.
  • MAC-Adresse: Layer-2-Adresse eines Netzwerkinterfaces.

IPv6

IPv6-Grundlagen

  • IPv6-Adressen sind 128 Bit lang und hexadezimal.
  • Global Unicast: global routbare Adressen, typischerweise 2000::/3.
  • Link-Local: fe80::/10, gilt nur auf dem lokalen Link.
  • ULA: fc00::/7 für interne Adressierung.
  • Neighbor Discovery ersetzt ARP; SLAAC und DHCPv6 können Konfiguration bereitstellen.
ipconfig /all
ip -6 addr
ip -6 route
ping -6 2001:4860:4860::8888

DHCP

DHCP und DORA

  1. Discover: Client sucht DHCP-Server.
  2. Offer: Server bietet eine Adresse an.
  3. Request: Client fordert das Angebot an.
  4. Acknowledge: Server bestätigt die Lease.

DHCP-Relay/IP-Helper leitet Anfragen über Router hinweg an DHCP-Server weiter.

ipconfig /release
ipconfig /renew
ipconfig /all
Get-DhcpServerv4Scope
Get-DhcpServerv4Lease -ScopeId 192.168.10.0
Switching & VLAN

VLAN, Access und Trunk

  • VLAN: trennt Layer-2-Broadcast-Domänen logisch.
  • Access-Port: ordnet Endgeräte einem VLAN zu.
  • Trunk-Port: transportiert mehrere VLANs, meist mit IEEE 802.1Q.
  • Native VLAN: ungetaggtes VLAN bei 802.1Q; Enden passend konfigurieren.
  • Inter-VLAN Routing: Kommunikation zwischen VLANs über Router oder Layer-3-Switch.
VLANs allein sind keine vollständige Sicherheitskontrolle. Kommunikation zwischen VLANs durch ACLs oder Firewallregeln begrenzen.
Routing

Routing-Grundlagen

Router leiten Pakete anhand der Routingtabelle weiter. Die längste passende Präfixroute (Longest Prefix Match) hat Vorrang. Eine Default Route dient als Ausweichroute, wenn keine spezifischere Route passt.

route print
tracert example.com
Test-NetConnection 192.0.2.1
ip route
ip route get 1.1.1.1
traceroute example.com

Statische Routen benötigen einen korrekten Next Hop oder ein Ausgangsinterface. Rückrouten sind ebenso wichtig wie Hinrouten.

Troubleshooting

Verbindung systematisch prüfen

  1. Link, WLAN, Interface und VLAN prüfen.
  2. IP-Adresse, Präfix, Gateway und DNS kontrollieren.
  3. Lokales Gateway testen.
  4. IP-Ziel und danach DNS-Namen testen.
  5. Routingpfad und Zielport prüfen.
  6. Firewall, ACL, NAT und Rückweg berücksichtigen.
ipconfig /all
arp -a
route print
ping 192.168.1.1
nslookup example.com
tracert example.com
Test-NetConnection example.com -Port 443
ip addr
ip route
ip neigh
dig example.com
ss -tulpn
