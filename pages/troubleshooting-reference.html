Troubleshooting – Erweiterte Referenz

Systematisch sortierte Befehle, Optionen, Praxisbeispiele und Diagnose. Platzhalter wie HOST, USER, SERVICE und IP an die eigene Umgebung anpassen.

Wichtiger Hinweis: Befehle und Optionen hängen von Betriebssystem, Version, installierten Modulen und Berechtigungen ab. Vor produktiven Änderungen Herstellerdokumentation, Testumgebung, Backup und Rollback prüfen. Beispiele sind Vorlagen, keine universellen Produktionskonfigurationen.

02 · Referenz

Layer-by-Layer Netzwerkdiagnose

Von physischer Verbindung über Link, VLAN, IP, ARP/ND, Routing, DNS, Transport bis Anwendung prüfen.

# Windows
ipconfig /all
arp -a
route print
nslookup example.com
Test-NetConnection example.com -Port 443
# Linux
ip -br addr; ip route; ip neigh; ss -tulpn

Parameter und Hinweise: Ping kann durch Firewall blockiert sein. Erfolgreicher Ping beweist nicht, dass TCP-Port oder Anwendung funktionieren.

03 · Referenz

DNS-Fehler systematisch

Client-DNS-Server, Record, Delegation, Cache und Erreichbarkeit getrennt testen.

Resolve-DnsName HOST
Resolve-DnsName HOST -Server 192.0.2.53
nslookup -debug HOST
ipconfig /flushdns
# Linux
dig +trace HOST

Parameter und Hinweise: Mit autoritativem DNS-Server vergleichen. Split DNS, Suchsuffix und negative Cacheeinträge beachten.

04 · Referenz

Windows Performance

CPU, RAM, Disk, Netzwerk, Prozesse und Eventlogs über denselben Zeitraum korrelieren.

Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
Get-Counter '\Processor(_Total)\% Processor Time'
Get-Counter '\LogicalDisk(_Total)\Avg. Disk sec/Read'
Get-WinEvent -LogName System -MaxEvents 100

Parameter und Hinweise: Einzelne Momentaufnahme ist keine Trendanalyse. Perfmon/Data Collector Sets für reproduzierbare Zeiträume nutzen.

05 · Referenz

Linux Performance

Load, CPU, RAM, Swap, Disk-Latenz, Inodes und Netzwerkdrops prüfen.

uptime
 top
free -h
vmstat 1 5
iostat -xz 1 5
df -hT
df -ih
ip -s link

Parameter und Hinweise: Load Average umfasst laufende und ununterbrechbar wartende Tasks; nicht direkt als CPU-Prozent interpretieren.

06 · Referenz

Windows Dienstfehler

Dienststatus, Starttyp, Abhängigkeiten, Konto, Rechte und System-/Anwendungslogs prüfen.

Get-Service -Name SERVICE
sc.exe qc SERVICE
sc.exe queryex SERVICE
Get-WinEvent -LogName System -MaxEvents 100
Test-NetConnection HOST -Port PORT

Parameter und Hinweise: Dienst nicht blind neu starten, wenn dadurch Datenverlust oder Failover ausgelöst werden kann. Wartungs- und Abhängigkeit prüfen.

07 · Referenz

Linux Dienstfehler

Unitstatus, Journal, Konfigurationssyntax, Rechte, Ports und Ressourcen prüfen.

systemctl status SERVICE
systemctl cat SERVICE
journalctl -u SERVICE -b --no-pager
systemctl --failed
ss -tulpn

Parameter und Hinweise: Nach Konfigurationsänderung passende Syntaxprüfung ausführen und Reload statt Restart bevorzugen, wenn unterstützt.

08 · Referenz

Docker Fehleranalyse

Containerstatus, Exit-Code, Logs, Healthcheck, Mounts, DNS und Port-Mapping prüfen.

docker compose ps -a
docker compose logs --tail 200 SERVICE
docker inspect CONTAINER
docker network inspect NETWORK
docker volume inspect VOLUME

Parameter und Hinweise: Kein docker system prune --volumes als erste Maßnahme. Erst feststellen, welche Daten persistent sind und ob ein Restore möglich ist.

09 · Referenz

Virtualisierungsfehler

Hostzustand, Datastore, virtuelle Switches, VM-Tools, Gastressourcen und Snapshotketten prüfen.

# Proxmox
pvecm status
pvesm status
qm status 100
# ESXi
esxcli storage filesystem list
esxcli network nic list
# Hyper-V
Get-VM; Get-VMSwitch

Parameter und Hinweise: Hostmanagement- oder Storageänderungen können mehrere VMs gleichzeitig beeinträchtigen. Out-of-band-Zugriff und Wartungsfenster sicherstellen.
