Docker – Erweiterte Referenz

Systematisch sortierte Befehle, Optionen, Praxisbeispiele und Diagnose. Platzhalter wie HOST, USER, SERVICE und IP an die eigene Umgebung anpassen.

Wichtiger Hinweis: Befehle und Optionen hängen von Betriebssystem, Version, installierten Modulen und Berechtigungen ab. Vor produktiven Änderungen Herstellerdokumentation, Testumgebung, Backup und Rollback prüfen. Beispiele sind Vorlagen, keine universellen Produktionskonfigurationen.
01 · Referenz

Images und Registry

Images sind unveränderliche Vorlagen; Container sind laufende Instanzen. Tags können veränderlich sein, daher produktiv kontrollierte Versionen/Digests einsetzen.

docker image ls
docker pull nginx:1.27
docker image inspect nginx:1.27
docker image history nginx:1.27
docker login

Parameter und Hinweise: Keine Zugangsdaten in Shell-History oder Image-Layern speichern. Registry-Zugriff über sichere Credentials verwalten.

02 · Referenz

Container-Lifecycle

Container starten aus Images und besitzen isolierte Prozesse, Netzwerk- und Dateisystemansichten.

docker ps -a
docker run -d --name web -p 8080:80 nginx:1.27
docker logs --tail 100 web
docker exec -it web sh
docker stop web
docker rm web

Parameter und Hinweise: -d detached; --name Name; -p HostPort:ContainerPort; -v Mount; --restart Neustartpolicy. Containerlöschung löscht nicht automatisch Named Volumes.

03 · Referenz

Docker Compose

Compose beschreibt Multi-Container-Anwendungen deklarativ in compose.yaml. Erst Konfiguration validieren, dann deployen.

docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f --tail 100
docker compose down

Parameter und Hinweise: up -d erstellt/aktualisiert Ressourcen; down entfernt Container und Netzwerk, aber standardmäßig nicht Named Volumes. down -v löscht Volumes – Vorsicht.

04 · Referenz

Netzwerke und DNS

Bridge-Netzwerke erlauben Containerkommunikation über DNS-Namen. Ports nur veröffentlichen, wenn Zugriff vom Host/Netz benötigt wird.

docker network ls
docker network inspect bridge
docker network create app-net
docker run -d --network app-net --name db postgres:16
docker inspect db

Parameter und Hinweise: Container im selben benutzerdefinierten Bridge-Netz können sich per Containernamen erreichen. Default bridge hat andere DNS-Eigenschaften.

05 · Referenz

Volumes und Bind Mounts

Named Volumes eignen sich für persistente App-Daten; Bind Mounts koppeln Hostpfade. Backup muss Anwendungskonsistenz berücksichtigen.

docker volume ls
docker volume inspect app-data
docker run -d --name db -v app-data:/var/lib/postgresql/data postgres:16
docker inspect db

Parameter und Hinweise: Datenbankdateien nicht unkoordiniert im laufenden Zustand kopieren. Native Dumps oder anwendungskonsistente Backupverfahren verwenden.

06 · Referenz

Logs und Ressourcen

Logs, Health, CPU und RAM helfen bei Diagnose. Logrotation auf Hosts konfigurieren.

docker logs --since 30m app
docker stats
docker inspect --format '{{.State.Health.Status}}' app
docker top app
docker events --since 1h

Parameter und Hinweise: Logs können Tokens oder personenbezogene Daten enthalten. Loggingtreiber und Aufbewahrung passend begrenzen.

07 · Referenz

Updates und Rollback

Vor Updates Imageversionen pinnen, Compose-Konfiguration sichern und Backup/Restore testen. Rollback erfordert kompatible Datenbankschemata.

docker compose pull
docker compose up -d
docker compose ps
docker image ls
docker compose logs --tail 200

Parameter und Hinweise: Ein älteres Image kann mit bereits migrierten Daten inkompatibel sein. Datenbankmigrationen vorab dokumentieren und Restorepfad testen.

08 · Referenz

Sicherheit und Hardening

Container möglichst unprivilegiert betreiben, Capabilities reduzieren, Secrets sicher zuführen und Images aktuell halten.

docker inspect --format '{{.HostConfig.Privileged}}' app
docker image ls --digests
docker info
# Beispieloptionen im Compose-Dienst:
# read_only: true
# cap_drop: [ALL]
# security_opt: [no-new-privileges:true]

Parameter und Hinweise: Privileged-Container vermeiden. Docker-Socket-Zugriff entspricht praktisch Host-Root-Rechten. Nicht benötigte Ports und Mounts entfernen.

09 · Referenz

Troubleshooting

Exit-Code, Logs, Inspect, Mounts, DNS, Ports und Healthcheck in dieser Reihenfolge prüfen.

docker compose ps -a
docker compose logs --tail 200 SERVICE
docker inspect CONTAINER
docker network inspect NETWORK
docker volume inspect VOLUME
ss -tulpn

Parameter und Hinweise: Nicht sofort prune oder Volumes löschen. Erst Datenpersistenz und Backupstatus verifizieren.
